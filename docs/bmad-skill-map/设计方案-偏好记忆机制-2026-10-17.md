# 设计方案：diy 偏好记忆机制（2026-10-17 呈审稿）

- 依据：BMAD 记忆机制调研（`调研结论-BMAD记忆机制-2026-10-13.md`）＋2026-10-17 用户裁定方向——人设载体不存在了，机制有用，读入按产物/技能挂载。
- 状态：五裁点待裁、未开工；裁后登底单待办段。

## 1. 需求边界（分家判据）

改产物内容的要求 → 进产物＋`revisions`（现有机制已覆盖，不进本机制）；
管「以后怎么制作」的要求 → 进偏好文件（本机制填补的缺口）。

## 2. 载体（裁点 1）

`{output_dir}/preferences.yaml`——键＝产物类型（与技能短名同键），值＝条目数组，**append 不覆盖**（BMAD 先例）。

- 随 `output_dir` 走＝instance 天然隔离；git 跟踪；与产物同域。
- 不落 `diy-coder.yaml`：其语义是安装期配置，且跨 instance 混居。

## 3. 读入（裁点 2）

`diyc.py resolve` 回执扩 `preferences` 键——50 技能激活必跑 resolve，回执带条目＝零新增步骤、模型读回执即见内容。

- 依据＝回执下沉先例（底单 :289 communication_language 同款）。
- 实现前提：resolve 现仅收 `--instance`（diyc.py:315），须加 `--skill <短名>` 旗标；各技能激活段统一句随批 8 母本标记对一趟注入（50 文件不另立改法）。

## 4. 写入（裁点 3）

AI 直写 append（bug-add「直写非给命令」先例）：用户说「记一下／以后 prd 都要 X」→ 落对应键。

- 不做 customize 对位技能（KISS：diy 无「升级覆盖技能文件」前提）。
- 不做 hook（批 8 同日已裁 hook 路线不做，维持）。

## 5. 保证（裁点 4）

- 写入面：`diyc check` 扩校验——preferences.yaml 在场则键名/格式合法；不在场合法（可选文件）。
- 读入面：回执带出＝数据在场保证；「模型照做」无关卡可设，承认概率区（底单 :288 判据），靠在场＋抽查。

## 6. 适用判据

进偏好：①项目个性/用户口味 ②管以后制作 ③不可机械化（概率区）④可随时追加。
不进（各有其主，进则双源）：

| 内容类型 | 归属 |
| --- | --- |
| 套件通用条款 | 母本 suite-texts（批 8；单条先行否决先例底单 :272） |
| 可机械规则 | 引擎关卡／母本 C 通道 |
| 踩坑经验 | experience_repo／bug-log |
| 安装配置（语言/路径） | diy-coder.yaml |
| 工程规则事实 | project-context `rules[]` |
| 产物内容与修改史 | 产物＋`revisions` |
| 建设期设计裁断 | 底单／任务书 |

## 7. 适用面盘点

### 7.1 底单裁断/未裁断件：零适用

1.1 已裁 7 件＋1.2 未裁 7 件逐件核：全部属建设期裁断（改代码/改技能/排期），无一属使用期制作偏好。例证：viewer 复制按钮「文案措辞随任务书拟」＝一次性拟稿任务非可追加偏好；FH 双口径＝引擎判定立法。H 件本身销项——原待裁三项（补不补/形态/层②③）被本方案吸收。

### 7.2 技能面（按产物制作自由度分档）

**高适合**（有产物、工艺自由度大、用户强调高频）：

| 技能 | 原因 |
| --- | --- |
| diy-prd | 利害档位/探索深度/路径口味——diy-lab 实测已有口径类要求实例 |
| diy-product-brief / prfaq / research | distillate 提炼口味、提问风格 |
| diy-design＋wds 线（brief/trigger/scenarios） | 呈现风格、优先级口味；schema 硬约束外自由区大 |
| diy-create-story / story-context | 验收标准写法、拆分粒度 |
| diy-test-design | 五轴覆盖深度、AC 写法口味 |
| diy-architecture | 决策记录详略 |

**中适合**（有产物但工艺大半已被机械/schema 承载，偏好只落剩余自由区）：

| 技能 | 原因 |
| --- | --- |
| diy-review | 判决规则/路由已机械；余「咬人尺度」口味 |
| diy-dev / test-author / e2e | 生成规则强；风格余区大半已被母本 §2＋lint 接管 |
| diy-openapi | schema 硬契约，自由区小 |

**不适合**：零产物五件套（elicit/party-mode/help/viewer/tools，无制作对象）；diy-tools/diy-bmb-*（产物是机制非文档）；investigate/analyze/reverse/readiness/selfcheck（判据+schema 固定，要求已在步骤立法）；语言输出类（diy-coder.yaml 语言键＋母本 §9 已管）。

### 7.3 写入入口（使用期来源）

- 制作中用户口述强调 → 本技能会话内直写（高适合技能激活统一句含写入口径）。
- review/selfcheck 发现 → 不进偏好（规格缺陷走 findings 路由；机制缺陷走底单）。
- retrospective → 不进偏好（踩坑进经验库；口味类可人工转记）。

5. 排期＝激活句搭批 8 母本窗、引擎两键随窗或独立小批？
