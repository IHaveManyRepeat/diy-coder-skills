# 调研结论：BMAD 记忆机制（2026-10-13）

对应底单待办「BMAD 记忆文件实存细看」。调研范围＝本仓 `_bmad/`（安装面）＋`/d/mycode/BMAD-METHOD`（源仓）＋`/d/mycode/diy-coder`（另一安装）＋`~/.bmad`（全局）。

## 一句话结论

BMAD 能记住强调的东西，**不是模型记住，是「偏好固化成文件＋技能激活时自动读入」**——核心载体＝`_bmad/custom/` 的 `persistent_facts` 机制；diy 迁移未覆盖此面，diy 现状靠宿主（Claude Code 的 CLAUDE.md 注入）兜住。

## 记忆体系全景（四层）

| 层 | 机制 | 实体 | 读取时机 | 本机实存 |
| --- | --- | --- | --- | --- |
| ①custom persistent_facts | 项目级偏好固化 | `_bmad/custom/<skill>.toml` 的 `[workflow]`/`[agent]` `persistent_facts[]`（`file:` 前缀引文件） | 技能激活时读入会话 | **本仓全套**（20 toml＋doc-style.md＋eng-defaults.md） |
| ②agent MEMORY | bmb 造的 agent 长期记忆 | agent sanctum：`MEMORY.md`＋`sessions/YYYY-MM-DD.md`＋`BOND.md`＋`INDEX.md` | MEMORY.md 每次唤醒加载；sessions 不加载（Pulse 时蒸馏用） | 零（模板实体在源仓 `.claude/skills/bmad-agent-builder/assets/`） |
| ③bmm sidecar | bmm agent 偏好记忆 | `_bmad/_memory/<agent>-sidecar/`（如 tech-writer 写 documentation-standards.md） | 技能运行中经 update-standards 类动作自写自读 | 零（注册在册 `bmad-help.csv:42`，三处安装均无目录） |

## 层①机制细看（核心，回答「为何强调能记住」）

**读取语义**（tech-writer SKILL.md:45 原文）：

> Treat every entry in `{agent.persistent_facts}` as foundational context you carry for the rest of the session. Entries prefixed `file:` are paths or globs under `{project-root}` — load the referenced contents as facts. All other entries are facts verbatim.

即：`persistent_facts` 条目＝本会话全程携带的基础上下文；`file:` 前缀＝把文件内容整体读入；裸字符串＝逐字当事实。

**写入通道**＝bmad-customize 技能（发现→选面→组 TOML→落位→验证五步）：用户说「customize bmad / change agent behavior」即触发；按目标技能的 `customize.toml` 暴露面写 `_bmad/custom/{skill}.toml`（team·committed）或 `.user.toml`（personal·gitignored）；`persistent_facts` 为 append 数组（叠加不覆盖）。

**本仓实存形态**（`_bmad/custom/`，gitignore 不入库）：

- `doc-style.md`（文档规范）——「精简至上：砍掉一切不改变决策的内容……」，挂到 prd／architecture／create-story／epics-stories／document-project／generate-project-context／domain-research／market-research 等约 12 个文档类技能的 `[workflow] persistent_facts`
- `eng-defaults.md`(工程默认)——pre-commit／CI／代码质量默认执行，挂到 agent-dev／dev-story 的 `[agent] persistent_facts`
- 其余 18 个 toml 为各技能覆盖配置

**证据**：doc-style.md 首句「默认执行，**无需用户强调**」＝设计意图直书——该文件内容与用户 CLAUDE.md「输出说重点，砍掉一切不改变决策的信息」同源，即用户强调过的偏好已被固化于此。每次跑 prd 等技能，激活步骤自动读入——这就是「记住了」的全部机制。

## 层②机制细看（bmb agent 记忆哲学）

源仓 `memory-guidance-template.md` 核心原文：

> You are stateless. Every conversation begins with total amnesia. Your sanctum is the ONLY bridge between sessions. If you don't write it down, it never happened.

两层结构：session 日志（原始·追加·**不加载**）→ Pulse（自主唤醒）时蒸馏进 MEMORY.md（精炼·**每次加载**·~1500 token 守护线，超线即修剪信号）；BOND.md 专记主人偏好。记什么有正反清单（记：决定、偏好、模式、有效/无效做法；不记：任务流水、可从项目文件推导的内容、原始对话、未明示要记的敏感信息）。

## diy 侧现状与缺口

- diy 50 技能**无任何「激活时读偏好文件」机制**；`persistent_facts` 同构面为零。
- diy 持久配置仅 `diy-coder.yaml`（communication_language／output_dir／experience_repo 等安装项）——一次性安装配置，非运行时偏好累积面。
- `experience_repo`（`~/.diy-coder/experience` 经验库）对应 BMAD 的经验文档层（层④经验面），非偏好记忆。
- 现状实际兜底＝宿主：Claude Code 每会话注入用户 CLAUDE.md——diy 技能「看起来记得」用户偏好，是宿主机制在起作用，diy 自身无此面。BMAD 在无宿主注入的场景（或偏好只该对 BMAD 技能生效时）靠 custom 层自持。

## 待裁项（diy 是否补记忆面）

1. **是否补 persistent_facts 同构面**——技能激活读项目级偏好文件（对齐层①）；不补则继续依赖宿主 CLAUDE.md（现状可用，但偏好对所有技能生效、无法按技能粒度挂载）。
2. **若补，形态**——diy-coder.yaml 扩偏好段 vs 独立偏好文件（doc-style 先例）vs 安装器通用项扩容；写入通道是否做（bmad-customize 同构）还是纯手工。
3. **层②③是否需要**——diy 无 persona agent（无 agent sanctum 概念），倾向不需要；层④经验面 diy 已有 experience_repo 对位。
