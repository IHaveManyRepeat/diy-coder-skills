# 夜间串行队列机制（定稿 v1.0 · 2026-10-18）

定位：无人值守夜间推进**已裁任务**的常设机制。每晚一次运行；每任务一个隔离提交单元；天亮人按序审、逐支合并。
载体＝技能 **`diy-coder/labs/diy-overnight/`**（产品套件同仓暂存、不接 install/sync 安装面；成熟后 `git mv` 进 `skills/` 即完成迁入）。本文档＝设计与裁定记录；运行协议以 SKILL.md 为准。
分支模型：**分支链**——每任务一支，新任务从上一任务分支 tip 切出（`overnight/YYYY-MM-DD/<任务id>`）；不 push；不碰 dev。
执行者：Claude 会话按技能协议执行——**不写新 runner 代码**（diy-build-loop/runner.py 面向目标项目 sprint 冲刺，与本域不同，不复用）。

## 1 授权模型

- **安全来自分支隔离，无需事前提交授权**：全部提交落在从 dev 新切的分支链上，dev/共享分支零触碰；每任务分支 tip＝该任务完整状态的具名检查点，用户可 checkout 亲验。
- **开工交互保留**（内容审＋时间定档）：晚间用户在场时完成前置检查＋队列过目＋deadline 定档，说「开工」即启动。
- **天亮人审＝按序逐支审、逐支合并**（流程详见 §9；审核与合并动作均归用户，夜班只建分支不动 dev）。
- 边界：不 push；不动 dev；**不裁断**（遇裁断点→阻塞还原，见 §4）。

## 2 产物

| 产物 | 落点 | 性质 |
|---|---|---|
| 队列 | `.analysis/overnight/queue.yaml` | 单一源：任务条目＋状态；滚动跨夜 |
| 晨报 | `.analysis/overnight/report-YYYY-MM-DD.md` | 当晚逐笔结果＋顺延/跳过/阻塞清单＋待裁点 |
| 分支链 | `overnight/YYYY-MM-DD/<任务id>` | 每任务一支一提交（tip＝绿点）；提交体含任务 ID／改动面／测试证据 |

## 3 队列条目

```yaml
- id: Q-001
  title: prfaq check root 归一
  basis: 底单「diy-lab 缺陷修复批」③（已裁·照 --previous 先例）
  scope: ["diy-coder/skills/diy-prfaq/scripts/prfaq.py", "diy-coder/tests/test_prfaq.py"]
  estimate_min: 40          # 预估分钟（小≤30／中≤60／大≤120）
  verify: []                # 除全量绿外的专项验收（如 sync 冒烟），无则空
  status: 待跑              # 待跑|进行中|完成|顺延|跳过|阻塞
  result: null              # 完成后写 {commit, tests, note}
  reason: null              # 顺延/跳过/阻塞原因
```

## 4 准入（入队四条件）

1. **全裁断**——当晚零裁断余地；任何「随批核／待裁」子点先行裁掉，否则不入队。
2. **改动面明确**且与他批无交叠；开工时工作树必须净（见 §5）。
3. **可独立 revert**——还原一任务不破坏已提交的他任务；依赖序显式排在队列顺序里。
4. 底单等共面文档仅在任务本体就是该文档作业时才入提交面（他窗改动不入）。

## 5 生命周期

### 开工前置（交互·用户在场）

1. 队列整肃：上晚 `完成` 条目归档（移 `archive` 段或删）；`顺延/跳过/阻塞` 留队重排。
2. `git status`：树不净 → **停**，列未提交面，用户裁处置（提交／stash／撤夜）。
3. 全量测试基线绿（HEAD 自证，~9min）。
4. 呈队列（顺序＋预估＋deadline 建议）→ 用户点头 → 「开工」。
5. 分支链起始锚＝dev HEAD（记 queue.yaml `base` 字段）；首任务分支在其绿时才创建（见执行循环）。

### 执行循环（无人值守）

对队列中每个 `待跑` 条目：

1. **时盒检查**（§6）→ 不满足则余下全部转 `顺延`，走收尾。
2. 置 `进行中`；从上一任务分支 tip（首任务＝base）检出实施；只动 `scope` 内文件。
3. 全量测试绿 → 建分支 `overnight/YYYY-MM-DD/<任务id>` 并提交（一任务一支一提交）→ 专项验收（`verify` 列表）→ 置 `完成`，记 `result`（分支名＋commit）。
4. **失败路径**（红修不动／超时／裁断点／中断）→ 工作区还原回上一任务分支 tip（含删自产未跟踪文件）——**失败任务不建分支、零提交痕迹**，天然可审计（分支链上只有绿点）→ 置 `跳过` 或 `阻塞`、记 `reason` → 下一任务。
   - 遇裁断点（实施中发现需新裁定）＝`阻塞`，**不代裁**。
   - **连续 2 任务跳过** → 疑系统性问题，余下全部顺延、收尾（防空转）。

### 收尾

1. 写晨报（§8）。
2. 不删分支——留早审。
3. queue.yaml 记当晚运行行（date／base／deadline／完成计数）。

### 中断恢复

会话崩溃后续跑：读 queue.yaml＋分支链定位（最后一支＝最新绿点）→ `进行中` 条目工作区改动**一律还原**回该 tip、置 `跳过(中断还原)`（不续做半成品）→ 仍在时盒内才继续循环。

## 6 时间盒

- deadline 开工时定（缺省 07:00 次日，可改）。
- **起跑门**：`now + estimate + 15min 测试缓冲 ≤ deadline`，否则顺延（=「7 点到、剩 4 个待办就暂停」的机械落法）。
- **超时门**：单任务实施超 `2×estimate` → 还原、`跳过(超时还原)`。
- **硬停**：deadline 后不起跑新任务；已在跑的给 45min 冲刺宽限（只许走到绿＋提交，不开新子工作）；宽限内到不了提交点 → 还原、`跳过(超时还原)`。

## 7 提交纪律

- **一任务一支一提交**：绿 → 从上一任务 tip 切 `overnight/YYYY-MM-DD/<任务id>` → 提交；提交信息 `feat|refactor|fix: 夜队列 <任务id> <标题>`（体：改动面／依据／测试数，照仓长文风格可精简）。
- 提交点＝全量 pytest 绿（现基线 1721＋248 subtests，~9min／轮）；tip 即绿点，checkout 可亲验复现。
- 不 push、不动 dev、不改已建任务分支；后任务发现前任务问题 → 本任务跳过或绕开，问题记晨报（前任务分支原样保留供早审裁断）。

## 8 晨报格式

```markdown
# 夜队列晨报 YYYY-MM-DD
base / deadline / 运行窗 / 完成 x · 顺延 y · 跳过 z · 阻塞 w

| 任务 | 状态 | 分支 | commit | 测试 | 备注 |
| Q-001 | 完成 | overnight/…/Q-001 | abc1234 | 1721+248 | … |

- 顺延/跳过/阻塞逐条：原因＋建议处置
- 待裁点收集（阻塞条目引出的）
- 早审指引：见 §9 逐支审核流程
```

## 9 早审顺序（用户逐支审、逐支合并）

晨报表格即审核顺序表（Q 号升序）。用户对每支三步走：

1. **看变更**：`git diff <前支 tip>..<本支 tip>`（首支＝`git diff <base>..<首支>`）；要亲验可 `git checkout <支>` 跑测试。
2. **裁断**：
   - **过** → `git merge <支> --no-ff`（或 ff）合入 dev；继续下一支。
   - **否** → 不合；坏件记底单待办（含分支名，现场保留供追查）；**继续下一支**——下一支基于坏支 tip，diff 仍干净可审；若好件与坏件有交叠冲突，cherry-pick 好件的单笔提交入 dev。
   - **拿不准** → 停，余支记待办次日裁。
3. **全部过完**后一次性处理：删分支链（`git branch -d overnight/YYYY-MM-DD/*`）＋归档 queue.yaml 完成条目。

中途 dev 前进不影响在审分支（分支链从 base 切出、互相独立于 dev 后续提交；合并冲突届时现解）。

## 10 裁定记录

2026-10-18 用户裁定：

1. **载体＝直接做技能**；落点＝产品套件同仓，**先不迁入安装面**（暂存 `diy-coder/labs/diy-overnight/`，成熟后 `git mv` 进 `skills/`）。
2. **早审顺序＝晨报表队列序，用户逐支审、逐支合 dev**（§9 流程）。
3. **数值五项照准**（deadline 07:00／宽限 45min／超时 2×estimate／连跳停机 2／测试缓冲 15min）——均为缺省值，开工定档时用户可逐项改。
4. **基线绿自证＝跑**（每晚前置第 3 步）。
5. **晨报落 .analysis，不入库**。
6. **机制文档定稿后提交 dev**。
