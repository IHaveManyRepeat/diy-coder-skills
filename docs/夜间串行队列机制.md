# 夜间串行队列机制（定稿 v1.0 · 2026-10-18）

定位：无人值守夜间推进**已裁任务**的常设机制。每晚一次运行；每任务一个隔离提交单元；天亮人按序审、逐支合并。
载体＝技能 **`diy-coder/labs/diy-overnight/`**（产品套件同仓暂存、不接 install/sync 安装面；成熟后 `git mv` 进 `skills/` 即完成迁入）。本文档＝设计与裁定记录；运行协议以 SKILL.md 为准。公共工具原语在 `rq_lib.py`（纯数据进出、无 CLI 依赖；随技能迁入时并入 diy-lib）。
分支模型：**分支链**——每任务一支，新任务从上一任务分支 tip 切出（`overnight/YYYY-MM-DD/<任务id>`）；不 push；不碰 dev。多队列接力沿用**同一开工日**，整晚分支落在同一目录下，删链一条命令。
执行者：Claude 会话按技能协议做调度（派 subagent／收回报／标阻塞）；机械循环由同目录 **`run_queue.py`** 强制执行（start/gate/done/fail/relay/report——2026-10-19 裁推翻 10-18「不写新 runner 代码」；2026-10-20 加 relay 队列接力；diy-build-loop/runner.py 面向目标项目 sprint 冲刺，仍不复用）。

## 1 授权模型

- **安全来自分支隔离，无需事前提交授权**：全部提交落在从 dev 新切的分支链上，dev/共享分支零触碰；每任务分支 tip＝该任务完整状态的具名检查点，用户可 checkout 亲验。
- **开工交互保留**（内容审＋时间定档）：晚间用户在场时完成前置检查＋队列过目＋deadline 定档，说「开工」即启动。
- **天亮人审＝按序逐支审、逐支合并**（流程详见 §9；审核与合并动作均归用户，夜班只建分支不动 dev）。
- 边界：不 push；不动 dev；**不裁断、不停等**（遇裁断点→阻塞还原→立即继续下一条，见 §5）。

## 2 产物

| 产物 | 落点 | 性质 |
|---|---|---|
| 队列 | 用户指定路径（激活时指定或询；本仓常用目录 `{仓根}/.analysis/overnight/`）；命名 `queue-<YYYY-MM-DD-HHMMSS>.yaml`（创建时间·年月日-时分秒，一晚一文件） | 单一源：任务条目＋状态；顶层 `next` 登记接力序 |
| 晨报 | 队列同目录 `report-<队列文件stem>.md`（与队列文件一一对应，如 `report-queue-2026-10-19-230830.md`） | 当晚逐笔结果＋顺延/跳过/阻塞清单＋待裁点；同晚多队列各一份 |
| 分支链 | `overnight/YYYY-MM-DD/<任务id>` | 每任务一支一提交（tip＝绿点）；接力沿用同一开工日；提交体含任务 ID／改动面／测试证据 |

## 3 队列条目

队列顶层字段：`test_cmd`／`base`（start/relay 写）／`tonight`（start/relay 写；relay 时另写 `relay_from`＝源队列）／`next`（接力序，路径相对本文件目录，缺省不接力）／`tasks`／`archive`／`runs`。

本仓 `test_cmd`＝`cd diy-coder && python run_tests.py`：有 `pytest-xdist` 时并行（`--dist loadfile` 按文件整包分配，规避 `os.chdir` 与模块级状态的跨文件串扰），缺失时自动安装；安装失败交互环境提示重试/串行，无人值守环境自动回退串行。串行后备：`python -m pytest tests -q`。

```yaml
- id: Q-001
  title: prfaq check root 归一
  basis: 底单「diy-lab 缺陷修复批」③（已裁·照 --previous 先例）
  scope: ["diy-coder/skills/diy-prfaq/scripts/prfaq.py", "diy-coder/tests/test_prfaq.py"]
  estimate_min: 40          # 预估分钟（小≤30／中≤60／大≤120）
  verify: []                # 除全量绿外的专项验收（如 sync 冒烟），无则空
  status: 待跑              # 待跑|进行中|完成|顺延|跳过|阻塞
  result: null              # 完成 {branch,commit,tests,tests_count,elapsed_sec,elapsed_min,test_sec,ratio,phases}；失败 {elapsed_sec,cause[,branch,commit,kept]}
  reason: null              # 顺延/跳过/阻塞原因
  started_at: null          # gate 写入（ISO 秒）
  done_at: null             # done 写入（ISO 秒）
```

填法实践（2026-10-19 裁）：**代码/引擎类任务 `verify` 不得空**——挂任务级专项断言（机械可判、零夜班裁断，如「构造重复键 YAML 跑 check 断言报 DUPLICATE_KEY」）；纯文档类可空（本仓文本探针＋早审兜底）。提交门只保回归，正确性由 verify 专项＋早审人裁双层兜底。

## 4 准入（入队四条件）

1. **全裁断**——当晚零裁断余地；任何「随批核／待裁」子点先行裁掉，否则不入队。
2. **改动面明确**且与他批无交叠；开工时工作树必须净（见 §5）。
3. **可独立 revert**——还原一任务不破坏已提交的他任务；依赖序显式排在队列顺序里。
4. 底单等共面文档仅在任务本体就是该文档作业时才入提交面（他窗改动不入）。

## 5 生命周期

### 开工前置（交互·用户在场）

1. 队列整肃：上晚 `完成` 条目归档（移 `archive` 段或删）；`顺延/跳过/阻塞` 留队重排。
2. `git status`：树不净 → **停**，列未提交面，用户裁处置（提交／stash／撤夜）。
3. 全量测试基线绿（HEAD 自证，~1.5min；并行前串行约 9min）。
4. 呈**接力链**（首队列＋`next` 登记的后续队列，各列任务序与 estimate 合计）＋deadline 建议（缺省次日 07:00）→ 用户可逐项改五数值（后续队列继承本档）→ 用户点头 → 「开工」。
5. 分支链起始锚＝dev HEAD（记首队列 `base` 字段）；首任务分支在其绿时才创建（见执行循环）。接力队列的 `base` 由 `relay` 写成接力时的 HEAD（＝上一队列末支 tip）。

### 执行循环（无人值守）

运行期连续执行、零停等：裁断点一律转阻塞后继续，禁止向用户提问或等待裁定（细则以 SKILL.md 为准）。

对当前队列中每个可跑条目：

1. **起跑门**（§6）不满足 → 脚本把余下待跑全转 `顺延`，走队列退出。
2. `gate` 领任务：建分支 `overnight/YYYY-MM-DD/<任务id>`、置 `进行中`（首任务从 base，此后从上支 tip）；只动 `scope` 内文件。
3. 实施＋自测 → `verify` 逐项过 → `done`：脚本跑全量（计时），**全量绿才 stage `scope`＋统一提交**（done 权威门，subagent 不自行提交）→ 写 result 置 `完成`。
4. **红回修**：`done` 红 → 反馈修，重跑；两次修复仍红 → 第三次 `fail --cause red --keep-branch`＝红标 WIP 提交留分支、切回链基点、置 `阻塞`（绿链零污染）。
5. **其他失败**：`fail --cause timeout|context|interrupt|ruling`（缺省零痕迹还原：检回链基点＋清 scope 自产未跟踪＋删失败分支）——`ruling`→`阻塞`（不代裁）、`context`→`跳过(子代理超限)`、`timeout`→`跳过`；`ruling` 落盘后立即回步骤 1，不向用户报告、不等待裁定。
6. **连跳熔断**：仅 `red`/`timeout` 计数，连续 2 → `circuit:true`，余下转 `顺延`。

**队列退出与接力**：队列无可跑条目后——先 `report` 写本队列晨报；熔断已触发 → 不接力、整晚收尾；否则 `relay`：源队列无待跑且树净时，按 `next` 顺序找下一队列，首个待跑任务过门（继承 deadline 与五数值）即初始化目标队列（`base`＝当前 HEAD、`tonight` 继承、`relay_from` 记录）并继续逐任务循环；目标不存在／进行中／无待跑／本晚已接 → 记 warning 跳过；门不过或无候选 → 整晚收尾。接力判定全在脚本。

### 收尾

1. 每个队列退出时已各写晨报（§8，`report-<队列stem>.md`，幂等）；整晚收尾汇总晨报路径与审核顺序（接力链序）。
2. 不删分支——留早审。
3. 各队列 YAML 记当晚运行行（date／base／deadline／计数／estimate 合计／实际合计／失败分布／熔断）。

### 中断恢复

会话崩溃后续跑：读队列＋分支链定位（最后一支＝最新绿点）→ `进行中` 条目工作区改动**一律还原**回该 tip、置 `跳过(中断还原)`（不续做半成品）→ 仍在时盒内才继续循环。接力链中崩溃：先定位有 `进行中` 条目的队列（即当前活跃队列）处置；已收尾队列晨报已落盘，其 `next` 接力照常。

## 6 时间盒

- deadline 开工时定（缺省 07:00 次日，可改）。
- **起跑门**：`now + estimate + 15min 测试缓冲 ≤ deadline`，否则顺延（=「7 点到、剩 4 个待办就暂停」的机械落法）。接力同口径：下一队列首个待跑任务不过门即整晚收尾。
- **超时门**：单任务实施超 `2×estimate` → 还原、`跳过(超时还原)`。
- **硬停**：deadline 后不起跑新任务；已在跑的给 45min 冲刺宽限（只许走到绿＋提交，不开新子工作）；宽限内到不了提交点 → 还原、`跳过(超时还原)`。

## 7 提交纪律

- **一任务一支一提交**：绿 → 从上一任务 tip 切 `overnight/YYYY-MM-DD/<任务id>` → 提交；提交信息 `feat|refactor|fix: 夜队列 <任务id> <标题>`（体：scope／basis／tests＋全量秒数）。
- **done 权威门**：提交由脚本 `done` 产生——脚本自跑 `test_cmd` 计时，全量绿才 stage＋提交（subagent 不自行提交）；红不提交不写盘，回修后重跑。
- **红标留审**：三次仍红 → `fail --cause red --keep-branch` 在任务分支打 `wip:` 提交、切回链基点、置 `阻塞`；红标只存在侧分支，绿链零污染。
- 不 push、不动 dev、不改已建任务分支；后任务发现前任务问题 → 本任务跳过或绕开，问题记晨报（前任务分支原样保留供早审裁断）。

## 8 晨报格式

文件名 `report-<队列文件stem>.md`（与队列文件一一对应，同晚多队列各一份）；运行行幂等追加 `runs`（estimate_合计／实际_合计_秒／失败分布／熔断）。

```markdown
# 夜队列晨报 YYYY-MM-DD

- base / deadline（宽限·超时·熔断·缓冲）/ 基线测试 / 运行窗
- 完成 x · 顺延 y · 跳过 z · 阻塞 w

| 任务 | 状态 | 预估 | 耗时 | 偏差 | 分支 | commit | 测试 | 备注 |
| Q-001 | 完成 | 40 | 38min | 0.95× | overnight/…/Q-001 | abc1234 | 1721+248 | … |

- 顺延/跳过/阻塞逐条：原因＋建议处置
- 待裁点收集（阻塞条目引出的；红标留审带 checkout 指引）
- 早审指引：见 §9 逐支审核流程
```

## 9 早审顺序（用户逐支审、逐支合并）

总审核顺序＝**接力链序**（前队列全部审完再审后队列）；每队列内按队列序（晨报表格行序）。用户对每支三步走：

1. **看变更**：`git diff <前支 tip>..<本支 tip>`（首支＝`git diff <base>..<首支>`）；要亲验可 `git checkout <支>` 跑测试。
2. **裁断**：
   - **过** → `git merge <支> --no-ff`（或 ff）合入 dev；继续下一支。
   - **否** → 不合；坏件记底单待办（含分支名，现场保留供追查）；**继续下一支**——下一支基于坏支 tip，diff 仍干净可审；若好件与坏件有交叠冲突，cherry-pick 好件的单笔提交入 dev。
   - **拿不准** → 停，余支记待办次日裁。
3. **全部过完**后一次性处理：删分支链（`git branch -d overnight/<开工日>/*`；接力沿用同一开工日，一条覆盖整晚）＋逐队列归档完成条目。

中途 dev 前进不影响在审分支（分支链从 base 切出、互相独立于 dev 后续提交；合并冲突届时现解）。

1. **载体＝直接做技能**；落点＝产品套件同仓，**先不迁入安装面**（暂存 `diy-coder/labs/diy-overnight/`，成熟后 `git mv` 进 `skills/`）。

4. **基线绿自证＝跑**（每晚前置第 3 步）。
5. **晨报落 .analysis，不入库**。
6. **机制文档定稿后提交 dev**。

2026-10-19 用户裁定：

1. **队列路径＝用户指定**（激活时指定或询），不写死 `.analysis/overnight/`；晨报落队列同目录。技能后续合入 diy 体系（`git mv` 进 `skills/`）时保持参数化。
2. **填法实践：代码/引擎类任务 `verify` 须挂专项断言**（§3）——全量绿只保回归不证正确，正确性由 verify 专项＋早审人裁兜底。
3. **执行分层＝agent team**（§6 执行循环）——主会话只当调度员，每任务的实施由 subagent 承担（按任务需要派单个 fresh subagent、多个 subagent 分工、或组 agent team 协作），子代理上下文干完即弃（主会话常驻跨任务），调度侧只收 `{branch, commit, tests, reason}` 回报，不吸收过程上下文；连跳熔断归因收紧为仅计红修不动/超时（子代理超限／中断还原不计入）；子代理上下文超限＝还原后 `跳过(子代理超限)`。动机：单窗口串行 7 任务必爆上下文，且爆上下文原会被误判为系统性问题触发熔断提前收工。
4. **机械循环下沉 runner 脚本**（2026-10-19，推翻 10-18 裁定 6「不写新 runner 代码」）——新建 `labs/diy-overnight/run_queue.py`（≤400 行·不接 install/sync 面）承载全部确定性动作：`start` 写 base＋tonight 五数值、`gate` 起跑门＋建分支＋状态写回、`done` 记 result、`fail` 零痕迹还原＋熔断计数、`report` 晨报＋runs 幂等追加；主 agent 循环中每步调脚本。动机：门／还原／熔断等硬规则由代码强制执行，不依赖模型自觉；脚本无上下文消耗，重启可续。windows 三坑已修（ruamel 读写锁 utf-8／git 输出锁 utf-8／树净校验排除队列与晨报）。
