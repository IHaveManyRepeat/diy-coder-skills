## 第 2 步 —— 结构与交互（源 step-02 第 1b / 1c 指令）

**先说清为什么**：讲清「为什么结构要和交互分开记」——结构回答「这一页有什么」，交互回答「它什么时候变」；混在一起，`states` 那一栏就永远是空的。用你自己的话讲。

### 2.1 页面结构（源 1b）

逐页记四段：**页头** / **主内容** / **页脚** / **侧栏**（有则记）。`url` 轨按 DOM 区块记，`screenshots` 轨按视觉分区记——**两种轨记的是同一件事**（区块顺序与容纳关系）。

### 2.2 交互与状态（源 1c）

逐页记：**悬停态**、下拉行为、表单校验、弹窗触发、加载态、响应式断点。

**与 `design.yaml` 的四态对齐**（这是本步最要紧的一栏）：四态 = `悬停` / `空态` / `加载中` / `错误`——能观察到的照实记，**观察不到的按最小真实信号记并注明**（例：静态内容页 `加载中: {signals: [文字]}` + 「无异步加载，保留占位」）；**绝不编造该页不会发生的行为**。

**落盘**：仍只在会话里（结构供 `03-specs` 的六段规格用，交互供四态用）。

**检查点（六拍）**：① 生成 → ② 落盘 → ③ 分隔 → ④ 呈出 → ⑤ 出四选项 → ⑥ 等响应。本步：② 落盘（本步无写盘）；④ 呈出结构与交互结论。 四选项同第 1 步。

## 第 3 步 —— 四张清单与重复值判据（源 step-02 第 1d 指令与清单段）

**先说清为什么**：讲清「为什么值要数一遍次数」——一个色只在一处出现，那是那个组件的局部决定，不是这套设计的规则；数出来才知道哪些是**体系**、哪些是**偶然**。用你自己的话讲。

### 3.1 四张清单（源清单段全保）

| 清单 | 记什么 |
| --- | --- |
| **页清单** | `#` / 页名 / URL 或路由 / 类型 / 关键区块 |
| **导航结构** | 主导航 / 副导航 / 页脚导航 / 移动端导航 |
| **组件清单** | 组件 / 变体 / 出现在哪些页 |
| **色板** | 名称 / 值 / 用途 |

### 3.2 字阶与间距（源 1d 后半）

**字阶**：层级 / 字号 / 字重 / 行高 / 用途。**间距**：基准单位与常用值（含区块内距、卡片内距、元素间距三类模式）。另收**圆角、阴影、断点**。

### 3.3 ★ 重复值判据（**「不抄像素」的机械面**，裁定 13）

收 token 之前，把候选值过一遍引擎：

```
python "{project-root}/.claude/skills/diy-reverse/scripts/reverse.py" tokens --values "<逗号分隔的候选值>" --project-root "{project-root}" --json
```

- 回执 `counts.tokens` = **出现 ≥2 次**的值（可作 token），`counts.dropped` = **单次值**（一律不收）。
- 判据同源：`design.py audit` 的 `one-off-color` / `one-off-font-size`——**单次值进了 token 集，正是它要抓的反面口径**。
- 〔**源侧自相矛盾的归一**〕源 `workflow-reverse-engineering.md:22`（抓规则不抄像素）与 `steps-r/step-02:113-126`（要采具体色值 / 字号）正文互斥（census-5 §4）。**本批取后者的一致性口径**：**允许把重复出现的值收作 token，禁止把单次值收作 token**。
- **哪一段是人工判定**：**计数可机械**（引擎），**分组与命名是人工判定**——哪些值归同一用途、要不要合并成阶，由你判并写进理由；这是本技能唯一不可机械的一段。

**落盘**：四张清单与 `tokens` 候选集进会话（真正的落盘在 `04-extract-tokens`）。

**检查点（六拍）**：① 生成 → ② 落盘 → ③ 分隔 → ④ 呈出 → ⑤ 出四选项 → ⑥ 等响应。本步：② 落盘（本步无写盘）；④ 呈出四张清单与重复值分流结果。 四选项同第 1 步。
