## 第 1 步 —— 定目标与访问轨（源 step-01 第 1–2 指令）

**先说清为什么**：讲清「为什么要先确认能不能进得去」——逆向的第一类失败不是看不准，是**看不着**：登录墙、限流、地区限制都会让后面每一页都建在猜上。用你自己的话讲。

### 1.1 目标四问（源 step-01 第 1 指令）

写清 `Target` / `Type`（网站 / Web 应用 / 组件库文档站 / 移动应用〔截图〕）/ `Owner`（自有 / 客户 / 公开 / 竞品）/ 一句用途。**只认外部目标**——「我自己的代码库」不在此列，见 1.2 的路由。

### 1.2 访问轨二选一（源 step-01 第 2 指令；**裁定 11 已裁去 Internal 轨**）

| 轨（`--track`） | 何时用 | diy 侧怎么抓 |
| --- | --- | --- |
| **`url`** | 公开网站 / 有演示的 Web 应用 | 套件内的 `agent-browser`（或等价浏览器工具）逐页打开与取证 |
| **`screenshots`** | 无实时访问、移动应用、客户给的图 | 逐图视觉分析 |

**访问限制照实记**（源 `login required, rate limits, geo-restrictions`）——它们是第 2 步门禁的失败分支，也是结构稿注释里要写清的话。

〔**用户裁决的能力裁撤（裁定 11）**〕源 `[R]` 原带第三轨 **Internal（分析自己的代码库，源码直读）**——它与 `[A]` 的重叠约 60%（census-5 §7.1），**本批裁掉**。**自有代码库 → 路由 `diy-analyze`**：一行说明「自有的按现状分析走 `diy-analyze`，本技能只做外部目标」，**零产出停止**。这是**路由**不是技能间调用——diy 的「调用」先例（`diy-elicit` / `diy-party-mode`）只给零写面增强技能；带产物的转交一律走路由（先例：`diy-design` → `diy-prd`、`diy-wds-scenarios` → `diy-wds-trigger`）。

## 第 2 步 —— 提取目标、门禁与铸骨架（用户关卡）

**先说清为什么**：讲清「为什么写权要在这里就判」——`design.yaml` 是主线的设计单一源，第二次落笔就是覆盖别人的演进成果。用你自己的话讲。

### 2.1 写权分支（**裁定 13**，先判后做）

先看 `{output_dir}/design.yaml` 在不在场：

- **不在场** → **初始生成**：走 2.2 的门禁与 `init`。
- **在场** → **不覆盖**：`init` 会判 `OVERWRITE_REFUSED` 并零写入。你的动作是**三件**：① 把本次想写的差异整理成 `revisions` **建议**（`{date, change, reason}`，`change` 点名 `P-<n>` 或字段名，**内容不复制**）在会话里呈出；② 一句话说明「生成权归 `diy-reverse`、演进权归 `diy-design` / `diy-dev`」；③ **路由 `diy-design`**（它的 Update 分支接这份建议）。

### 2.2 门禁（`init` 机械兜住）

**门禁 = 外部目标可访问**（本技能无上游 diy 产物）：

- `url` 轨：目标须是 `http://` / `https://` 开头的公开目标——形态不合法 → `TARGET_UNREACHABLE`、零产出。
- `screenshots` 轨：截图路径须存在且可读——否则 `TARGET_UNREACHABLE`、零产出。
- **真实可达性由你验**（打开一次 / 读一次图）——引擎只核形态与在场；**没验过不许往下走**。

### 2.3 用户关卡与铸骨架

把「目标 / 访问轨 / 提取目标 / 写权分支」四项摆成一块呈批，**没拿到明确点头就不许往下走**；点头后调引擎：

```
python "{project-root}/.claude/skills/diy-reverse/scripts/reverse.py" init --track "<url|screenshots>" --target "<URL 或截图路径>" --project-root "{project-root}" --output-dir "{output_dir}" --json
```

- 铸出的是**既有 schema 的空壳**（`project.status: 草稿`、`direction` / `frontend_framework` / `tokens` 三段置空、`pages: []`）——**不新增字段、不自造 ID 形态**。
- `project.name` / `created` 由 `init` 铸造后**不再由你改**；页 ID 到 `03-specs` 才顺序铸。
- **「提取来源」写哪**：骨架阶段就把它记进**本批的会话上下文**——收尾时落在每份结构稿的头部注释（`<!-- 提取来源: <url> / <截图名> · 采集日 YYYY-MM-DD -->`）与会话呈出；`design.yaml` 无来源字段，本批**不新增**（登记为 C·3 的 schema 扩充项）。

**检查点（六拍）**：① 生成 → ② 落盘 → ③ 分隔 → ④ 呈出 → ⑤ 出四选项 → ⑥ 等响应。本步：② 落盘（`init` 铸骨架）；④ 呈出回执与骨架摘要。 四选项同第 1 步。

**收尾与路由**：目标与写权都清了，读 `./02-explore.md` 起广度侦察。
