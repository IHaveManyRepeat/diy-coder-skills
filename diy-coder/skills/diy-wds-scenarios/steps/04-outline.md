## 第 1 步 —— 载模板与 8 问对话（源 step-05 第 1–3 指令）

**先说清为什么**：讲清「什么是交易」——**不只是下单和预约**：一页一页读完站上的内容算交易，来回比几家算交易，凡是「带着意图在站上走过一段」都算（源侧原话）。用你自己的话讲。

**处理顺序**：按 `priority` 升序（`1` 先）；`init` 铸的 `SC-01` 就是第一条。回访（循环回来）时接着下一条 `status: 草稿` 的走。

**两种模式，同一套 8 问**（源 step-05 第 3 指令）：

- **对话模式**（默认，`scope.approach: 对话`）：**你问，用户答**，一次一问，上一答决定下一问怎么问。
- **建议模式**（`scope.approach: 建议`，或用户中途说「你先给」）：**你按触发图 + 简报把 8 问全答出来**，整条呈给用户改。

**8 问**（源 step-05 逐问；「坏例 / 好例」是源侧原文给的判据，**别丢**）：

| # | 问 | 落哪个键 | 判据（源侧好/坏例） |
| --- | --- | --- | --- |
| Q1 | **哪一笔交易必须做对？** | `transaction` | 说成用户的目的，不是功能名。坏：「首页和服务页」；好：「下单前先确认服务在不在」 |
| Q2 | **这笔交易成了，喂到哪条业务目标？** | `trigger_map_context.business_goal` | 引触发图里的**真目标**——这一问把场景钉在生意上 |
| Q3 | **谁最常遇上它，当时是什么处境？** | `situation` + `trigger_map_context.target_group` | 不只是「谁」，是「谁、在哪、什么时候」。坏：「一个找信息的客户」；好：「Hasse，55 岁，房车在 Byxelkrok 抛锚，正带着家人度假」 |
| Q4 | **他进来时想要什么、怕什么？** | `driving_forces.hope` / `.worry` | 盼与怕都要**具体可感**；**一组件一句**，短语不是段落。坏：「用户对产品感兴趣」；好：「盼：附近有靠谱修理厂，今天就上路。怕：被困好几天、被不认识的修理厂宰」 |
| Q5 | **他手上是什么设备？** | `device` | 手机 / 桌面 / 平板——它决定整个设计取向 |
| Q6 | **他实际是怎么来的？** | `entry` | **1–2 句**：设备 + 处境 + 发现方式。坏：「用户打开网站」；好：「在加油站用手机搜『修车 Öland』，点了自然结果第一条」 |
| Q7 | **最好的结果长什么样——两边各得到什么？** | `success.user` / `.business` | 两边都要具体可量。坏：「用户成功用了网站 / 拿到更多客户」；好：「用户：确认这家修房车、有位置和营业时间、敢打电话；生意：拦下一条高意向来电，被认成能救急的，省掉一次问询」 |
| Q8 | **站上最短的一条路怎么走？** | `pages[]`（见第 3 步） | **完全线性、零「如果」、零分支**；步数**最省**（每一步都要说得清为什么删不掉） |

**交易边界（源侧的补充口径）**：点菜单一项项读内容算交易、比选项算交易——别把「交易」窄化成购买或预约。

**落盘**：8 问的答案在本步仍**只在会话里**；第 3 步一次写进记录（逐问写、不要漏键）。

**检查点（六拍）**：① 生成 → ② 落盘（本步无写盘，记 8 问结论）→ ③ 分隔 → ④ 呈出这一条场景的 8 答 → ⑤ 出四选项 → ⑥ 等响应。

## 第 3 步 —— 落 `scenarios[]` 记录与 `pages[]`（源 step-05 第 6–7 指令；**裁定 12 改判**）

### 3.2 页面记录（`SC-<nn>.P<n>`；源页面样板的键）

Q8 的每一步落一条 `pages[]`（**源侧「首步自动处理 + 之后逐步补」的节奏照旧**）：

```yaml
      - id: SC-01.P1            # 父子引用：前缀必须等于所属场景的 ID
        slug: 01.1-home          # 展示名：NN.<p>-<页 slug>，NN.<p> 必须与 ID 同源
        name: 首页
        purpose: <用户在这一页要达成什么>       # 源 Page Purpose
        entry_context: <上一页的什么动作带来这里>  # 源 Entry Context
        exit_action: <什么动作带去下一步>        # 源 Exit Action；末页可省（收在成功态）

```

**首步（P1）的三件**（源侧「第一步另加」的用户处境 / 心理状态 / 发现方式）：**不另立键**——它们就是本场景记录的 `situation`（Q3）/ `driving_forces`（Q4）/ `entry`（Q6）。**这是刻意的单一源**：同一件事不写两遍（源侧样板在场景文件与页面文件夹里各存了一份）。

**两类交互**（源 step-05 的分法，照旧）：**离开本页** → 新起一条页面记录（新页号）；**留在本页** → 记进 `on_page_interactions`。

**落盘**：`scenarios[]` 正文与 `pages[]` 一次写齐 → 把该条 `status` 推到 `已大纲` → 跑一次 `check`（草稿体检：覆盖矩阵会点名还没分配的页）。

## 第 4 步 —— 逐页串行与循环（源 step-05 第 7 指令）

### 4.1 场景步菜单（每落完一条页面记录就出一次）

```
SC-01 的第 X 页「<页名>」已落！

1. 继续下一页 — <Q8 里下一步的页名>          # 走「每步两问」再落一条记录
2. 直接进设计 — 这条场景先收口（design_intent 拍定见 06-finish）

---
[N] 定下一条场景
[C] 全部做完，进总览（所有场景都已大纲时）
```

**自适应标签**（源侧口径照旧）：Q8 的页全落完时**选项 1 不再出现**，改示「X 页已全部落完！」；选项 2 在只有 1 页时写「直接进设计」、2 页以上写「直接进设计（从第 1 页起）」。

**选项 2 的 diy 口径（断头路声明）**：源侧它转进 Phase 4 UX Design。**WDS 线止于本技能**——`diy-design` 要吃的是主线 `prd.yaml` 的双源输入，在 **C·3** 之前不接本线。故 diy 侧该选项 = **把当前场景收口**（`status: 已大纲` + 记 `design_intent`），并一句话说明设计线未接线；**不许**假装能转过去。

### 4.2 每步两问（源 Per-Step Dialog）

每条非首条页面记录，先问两句再落：**① 这一步的意义是什么**（用户在这页要达成什么 → `purpose`）；**② 他做什么才能往前走**（→ `exit_action`；若这个动作**留在本页**，改记 `on_page_interactions`，页号不加）。

### 4.3 循环判定（源 step-05 的 loop）

- 方案里还有场景没做 → 回第 1 步（下一条按 `priority` 取），**场景级 `[N]`**；
- 还有页没落 → 留在本步接着落；
- **方案里每条场景都 `status: 已大纲`** → 只有这时 `[C]` 才成立（源 `only when ALL scenarios from the approved plan are outlined`），读 `./05-overview.md`。

**落盘**：每次循环只动当前这条记录；`revisions` 不因逐页推进而写（推进锚点是记录级 `status`）。

**检查点（六拍）**：① 生成 → ② 落盘 → ③ 分隔 → ④ 呈出菜单与当前进度 → ⑤ 出选项 → ⑥ 等响应。四选项同第 1 步，只是此处以 4.1 的菜单为主。

**收尾与路由**：全部场景已大纲，读 `./05-overview.md`。
