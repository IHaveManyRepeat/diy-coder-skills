## 第 2 步 —— 命名铁律、ID 定稿与记录落盘

### 2.1 命名铁律（源 step-04 第 2 指令；**骨律**）

**场景名必须含人物名**——「<人物名> 的 <目的>」：

- 好：「Hasse 的紧急求助」「Lars 查工作坊时间」「Åke 协调车队保养」
- 坏：「紧急预约流程」「查时间」「服务排期」

**为什么**：名字里带着人，整条设计过程就一直在想着那个人（源 `Keeps persona psychology front-of-mind throughout design`）。人物名从 `wds-trigger.yaml` 的 `personas[].name` **逐字取**（不译、不改写）。

### 2.2 ID 定稿（源的 `NN` 约定 → diy 的 `SC-<nn>`，裁定 8）

| 件 | diy 形态 | 说明 |
| --- | --- | --- |
| 场景 ID | `SC-01` / `SC-02` … | 两位序号、**顺序递增**、不重编不复用；`SC-01` 已由 `init` 铸好 |
| 展示名（slug） | `<nn>-<人物名拼音>-<目的>` | 源侧 slug 形态保留作展示名；**引用一律走 ID** |
| 页面 ID | `SC-<nn>.P<n>` | 到 04-outline 逐页长出来；**废止源侧独立 `P-*` 前缀** |
| 人物引用 | `TG-<n>` | 引用键，不复制人物名与驱动因素原文 |

**场景按优先级排**：`priority: 1` 的排在前面——`SC-01` 就是 P1 的那条（源 step-05「先做首要交易」）。

### 2.3 记录落盘（编辑产物，写权归会话）

逐条写 `scenarios[]`（**只写计划级键**，8 问的正文留到 04-outline）：

```yaml
scenarios:
  - id: SC-01                     # init 已铸；其后各条按 SC-<nn> 顺序追加
    name: "<人物名> 的 <目的>"      # 命名铁律
    priority: 1                   # 1 关键路径 / 2 支撑 / 3 边角
    status: 草稿                   # 记录级推进锚点：草稿 → 已大纲
    trigger_map_context:          # 交接契约（裁定 17），C·3 的 diy-design 按它取锚
      target_group: TG-1
      drivers: [DF-1.1+, DF-1.2-]  # 所消费的驱动因素 ID（**引用不复制**；形态同上游）
      business_goal: BG-1          # 上游 business_goals[].id
```

**引用键取自上游实值**（`wds-trigger.yaml`）：人物 `TG-<n>` · 驱动 `DF-<人物号>.<条号>+|-` · 目标 `BG-<n>`。**所消费的驱动必须属本记录的人物群**——跨群引用引擎会判违规（`SET_MISMATCH`）。

- `SC-01` 那条已由 `init` 铸出（只有 `id` / 空 `name` / `status`）——**就地补齐**，不要另起一条。
- 追加 `SC-02` … 时**照着上面的键写**；ID 连不连续、有没有重号，跑 `check` 机械核。
- **`trigger_map_context` 必携**：没有它，C·3 的 `diy-design` 取不到「这条场景为谁、为什么」。

**落盘**：`scenarios[]` 写完 → 跑一次

```
python "{project-root}/.claude/skills/diy-wds-scenarios/scripts/wds_scenarios.py" check --project-root "{project-root}" --output-dir "{output_dir}" --json
```

看三样：ID 链（跳号 / 重号会报 `SET_MISMATCH` / `DUPLICATE_ID`）、覆盖矩阵（还没分配的页会逐条点名）、令牌与枚举。**这一跑只是草稿体检**，`--final` 才是终门。

**检查点（六拍）**：① 生成 → ② 落盘 `scenarios[]` 计划记录 → ③ 分隔 → ④ 呈出记录摘要 → ⑤ 出四选项 → ⑥ 等响应。四选项同第 1 步。

**收尾与路由**：计划已批、记录已落，读 `./04-outline.md` 逐场景做大纲。
