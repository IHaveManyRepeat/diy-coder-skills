## 第 1 步 —— 战略链与 7 问决策矩阵（源 step-03 第 1 指令）

**先说清为什么**：讲清「什么叫一条战略链」——从生意上的一个目标，找到最在意它的那个人，再落到他此刻的怕与盼，最后落成他能做的一件事。用你自己的话讲，配一个源侧的例子：

```
<业务目标> → <人物（优先级）> → <驱动因素（怕或盼）> → <交易：用户做的那件事> → <候选场景名>
例：少接 40% 的问询电话 → Hasse（P1，慌着的游客）→ 怕：车坏在半路没人管
    → 交易：确认这家修不修房车 + 拿到怎么走 → SC-01「Hasse 的紧急求助」
```

**逐条业务目标**（源 step-03 第 1 指令的四问）：这条目标最直接由**哪个人物**推动？他**哪条驱动因素**（盼的或怕的）挂在这条目标上？他为此要做的**那一件事**是什么？用他的名字给候选场景起个名。

**7 问决策矩阵**（源 step-03 的 7 问，「7 问全答」是 32 闸里的一条）：

| # | 问 | 答（写进链） |
| --- | --- | --- |
| 1 | 服务哪条业务目标？ | 触发图里的具体目标 |
| 2 | 哪个人物？ | 姓名 + 优先级（`TG-<n>`） |
| 3 | 哪条驱动因素？ | 具体的盼或怕（**引用**其 ID / 路径，不复制原文） |
| 4 | 交易是什么？ | 用户做的那件具体事 |
| 5 | 他从哪来？ | 现实的起点（具体到场景，不是「打开网站」） |
| 6 | 他得到什么价值？ | 摸得着的结果 |
| 7 | 生意得到什么价值？ | 量得出来的结果 |

**落盘**：链是**会话内**的中间物——7 问的答案到 03-plan 第 2 步随记录一起落 `scenarios[]`（`transaction` / `situation` / `driving_forces` / `success` / `trigger_map_context`）。

## 第 2 步 —— 页面分配、优先级与覆盖核查（源 step-03 第 2–4 指令）

### 2.1 页面分配（源 step-03 第 2 指令）

逐条链列出它用到的页（从第 1 步铸好的 `page_inventory[]` 里取，**页名逐字对齐**——它是覆盖矩阵的连接键）：

- **每页恰属一条链**（不重复）；
- 一页看着能进多条链 → **分给优先级最高的那条**，不是两边都写；
- **共用元素不参与分配**（页头 / 页脚 / 导航）。

### 2.2 优先级三层（源 step-03 第 3 指令）

| 层 | 判据 | `scenarios[].priority` |
| --- | --- | --- |
| 关键路径 | 最高业务目标 + 首要人物 + 产品核心价值——**先做、做最细** | `1` |
| 支撑 | 次要人物的场景、替代入口——重要但不是战略核心 | `2` |
| 边角 | 管理类任务、稀有用户群、出错恢复——可推后 | `3` |

### 2.3 覆盖核查（源 step-03 第 4 指令的四项；**每一条都要真的过一遍**）

- [ ] 页清单里的**每一页**都分给了**恰一条**链；
- [ ] 首要人物至少有**一条 P1** 场景；
- [ ] 最高业务目标**至少被一条**场景承接；
- [ ] **没有一页**出现在多条链上。

**有页落单** → 扩一条链或把落单页并进现有链（源 `Create additional scenario chains or expand existing ones`），**不许留着不管**。

### 2.4 呈出链清单（源 step-03 第 5 指令）

```
## 战略链

### 优先级 1
**链 01：** <业务目标> → <人物> → <驱动因素> → <交易>
- 候选场景：SC-01
- 页：<列表>

### 优先级 2
…

**覆盖：X/Y 页已分配**
```

**落盘**：链清单与分配方案仍是会话内的中间物；`page_inventory[]` 若在核查中补了页，**当场编辑产物**补条（页清单的写权在你）。

**检查点（六拍）**：① 生成 → ② 落盘（补齐的页清单）→ ③ 分隔 → ④ 呈出链清单 → ⑤ 出四选项 → ⑥ 等响应。四选项同第 1 步。

**收尾与路由**：覆盖核查四项全过（或已按 2.3 补齐），读 `./03-plan.md` 起场景计划。
