# 迭代精修纪律（3 轮）

> **出处**：源 `wds-6-asset-generation/data/prototype-to-figma-workflow.md`（933 行，随 `[E]` 活动一并裁撤）里的**迭代环**——**与外部服务无关**，故按裁定 6 的处置**摘留**（源 :56–:150）。
> **diy 化的那一拍**：源侧中段的「extract to Figma → 在 Figma 里精修 → 读回」换成「**用户拿导出的提示词在外生成 / 本地直接改 HTML**」——**语义不变**（都是「先粗后精、把精修得到的具体值落回设计系统」），只是中间那件工具不存在了。

## 三拍

### 第一拍：基本版

**输入**：页面规格 / 设计系统 / 视觉方向（本技能前三步读到的那些）。
**产出**：能用但不精致的件——功能对、结构对、样子糙。
**评 估**：功能上跑得通吗？样子够看吗？
流水：草图 → 规格 → 出 HTML/CSS → 得到一个「基本版」。

### 第二拍：视觉精修

**做什么**：补字阶、调色板、改间距与内边距、加视觉层次（阴影 / 边框 / 效果）、补缺失的变体、定义态。
**关键动作**：**把改出来的值记下来**——记的是**值**（`#2563EB`、`16px`、`700`），不是截图。源侧口径原话是「Document Design Decisions」，落成本技能就是 `items[].token_ref` 与 `revisions` 里的一条。

### 第三拍：用增强后的设计系统重渲

**做什么**：把第二拍得到的新值**合并进设计系统**，然后用新令牌**重出**。
**diy 侧的写权**：设计系统归 `diy-wds-system`——本技能**不改它**，只在 `revisions` 里提一条建议（「`color.primary.600` 建议由 `#1D4ED8` 调整为 `#2563EB`，来源 = `AS-02.3` 的第二拍精修」）。

## 三条判据

1. **一轮结束时必须答得出**「这一轮改了什么值、为什么」——答不出来就不是精修，是瞎调；
2. **一轮一个维度**——第二拍改视觉，不要同时动结构（同时动 = 归因不了是哪一处起的作用）；
3. **第三拍之后还有问题就回到第一拍**——重出基本版，不是继续在精修层堆补丁。

## 与「4 条红旗」的分界

本文件管**怎么迭代**；`data/stop-red-flags.md` 管**什么时候该停**。两件都在 `steps/09-finish.md` 第 3 步过一遍：**红旗先于轮次**——出现任一条红旗，轮次立即中止。
