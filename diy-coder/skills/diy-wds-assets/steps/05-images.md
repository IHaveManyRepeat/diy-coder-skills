# Step 5 — 图片（M）

Progress: `[1 载图位上下文] → [2 盘点与分批] → [3 按批选成像技法] → [4 参考图与参考链] → [5 批量生成] → [6 成套评审]`

**Read (input):** `{output_dir}/wds-scenarios.yaml` 的 `scenarios[].pages[]`（图位需求：故事 / 尺寸比 / `alt` 文案）；`{output_dir}/wds-brief.yaml` 的 `brief.visual`（摄影指引 / 色和谐 / 调性 / 题材偏好与禁忌）；`{output_dir}/wds-design-system.yaml` 的图像令牌（比例 / 圆角 / 叠加 / 断点容器）；品牌素材与 `{output_dir}/assets/images/` 既有件；`data/styles/content-styles/` 目录（10 张卡）。
**Write (output):** `wds-assets.yaml` 的 `activities[AS-05]`；`{output_dir}/assets/images/` 与 `prompts/`。

你是**图片生产的主持人**（源 `steps-m/` **六步**——本技能唯一多出「参考图」独立一步的活动）。图片是**按批生产**的：一批一致，胜过一张漂亮。

**本段纪律**：① **参考链是本活动的机制**（锚图先行 → 批准件作参考 → 偏离的回退重出），不是建议；② **不接外部服务**（裁定 6）——`[U] 上传既有` 分支保留（用户手上已有图就登记路径，不重复生成）；③ **原创提示词随产物留档**（源侧口径：原始提示词作元数据）。

## 第 1 步 —— 载图位上下文（源 `steps-m/step-01`）

**先问清**：「这一轮要出哪些图？品牌素材你手上有现成的吗？」

**读四样**：
1. **图位需求**——从页面规格抽：每张图的**故事**（它要说什么）、**尺寸比**（hero `16:9`、product `1:1` 这类）、`alt` 文案（**无障碍用，不许留空**）；
2. **视觉方向**——`brief.visual`：摄影指引 / 色和谐 / 调性 / 题材偏好 / **禁忌**（禁忌要单独列出来，写进提示词的负向词）；
3. **图像令牌**——比例 / 圆角 / 叠加（overlay）/ 断点容器宽；
4. **既有素材**——扫 `{output_dir}/assets/images/` 与品牌素材目录：可复用的标 `复用`，要生成的标 `待生成`。

**产出键**：`activities[AS-05].status: 进行中` + `stage: 图片`；摘要会话内呈出（张数 / 六类分布 / 调性 / 可复用数 / 待生成数）。

**检查点（六拍）**：① 生成摘要 → ② 落盘活动 `status` / `stage` → ③ 分隔 → ④ 呈出 → ⑤ 出四选项 → ⑥ 等响应。
`[a]` 高级引导 → 调 `diy-elicit`（零写面）｜ `[c]` 继续 → 进下一步 ｜ `[p]` 多方模式 → 调 `diy-party-mode`（零写面）｜ `[y]` YOLO → 跳过后续检查点连续推进（首次选中时一行明示）。

读全并照做本文件 `## 第 2 步 —— 盘点与分批`。

## 第 2 步 —— 盘点与分批（源 `steps-m/step-02`）

**先问清**：「按什么分批——按类型、按页，还是一次全上？」

**图位清单表**：逐条写 **名 / 页 / 类别 / 尺寸比 / alt 文案**。

**按六类分批**（源侧原口径）：`hero` / `product` / `people` / `background` / `illustration` / `decorative`。批次是本活动的**生产单位**（一批一种光、一种调性）。

**批量机会识别**（源侧原话的落地）：「17 张车图 = 一批」「全团队照 = 一种光」——凡是**同题材 + 同调性**的都并成一批，一批一提示词模板 + 每张的差异行。

**范围四选一**（写进 `activities[AS-05].scope`）：`all` / `batch`（按批）/ `select` / `priority`。

**产出键**：`activities[AS-05].items[]`（`id: AS-05.<m>` 递增；`name` / `pages` / `size`（比例，如 `"16:9"`）/ `spec` / `variant`（批名）非空）。

**检查点（六拍）**：① 生成清单与分批表 → ② 落盘 `items[]` / `scope` → ③ 分隔 → ④ 呈出 → ⑤ 出四选项 → ⑥ 等响应。四选项同第 1 步。

读全并照做本文件 `## 第 3 步 —— 按批选成像技法`。

## 第 3 步 —— 按批选成像技法（源 `steps-m/step-03`）

**先问清**：「这批走写实摄影，还是插画 / 水彩 / 等距？」

**内容风格按批分配**：读 `data/styles/content-styles/` 目录（10 张卡：`3d-render` / `comic-book` / `flat-design` / `hyper-realistic` / `illustration` / `isometric` / `line-art` / `pencil-sketch` / `photorealistic` / `watercolor`），**一批选一张**（**不同批可以不同卡**——这是 content-styles 与 design-styles 的用法差别，后者是整站一张）。写进 `activities[AS-05].style.content`。

**视觉参数四件**（源侧原口径，逐批定）：光（方向 / 软硬 / 色温）｜ 色和谐（与令牌的关系）｜ 构图（主体位置 / 留白方向）｜ 调性（暖冷 / 静动）。

**风格卡关键词**：把选中卡的 `Prompt Keywords` **逐词**带上（英文原样）。`Dimensions Guide` 里的比例若与图位需求冲突，**以图位需求为准**（卡是参考，页面规格是硬要求）。

**产出键**：`activities[AS-05].style`（`content` 必填、`design` 可空——图片不读 design-styles）+ `items[].token_ref`。

**检查点（六拍）**：① 生成按批分配表 → ② 落盘 `style` / `token_ref` → ③ 分隔 → ④ 呈出 → ⑤ 出四选项 → ⑥ 等响应。四选项同第 1 步。

读全并照做本文件 `## 第 4 步 —— 参考图与参考链`。

## 第 4 步 —— 参考图与参考链（源 `steps-m/step-04`，**本技能唯一的独立参考步**）

**先问清**：「这批有品牌摄影 / 情绪板 / 之前批过的件可以当参考吗？」

**参考图分类与计数**：把可用参考分成四类——**品牌摄影 / 情绪板 / 前次批准件 / 风格样例**，逐类计数。

**每批 `1–3` 张，且每张注明用途**（源侧原口径）：这张是为了**调性**、还是为了**取景**、还是为了**质地**——用途不写清，参考图就只是噪音。

**参考链策略**（源侧原口径，三步固定）：
1. **批内首图不带参考**（锚图从零出，避免把上一批的特征拖进来）；
2. 锚图**批准后作本批第二张的参考**；
3. **偏离者**（与锚图气质不合的）用**最接近的批准件**重生——不是用最早的锚图硬掰。

**落盘口径**：参考图**登记路径引用**（`items[].review.checks` 里写明用了哪几张）；本技能不复制外部素材进 `assets/`。

**产出键**：`items[].review.checks` 追加参考链记录（`anchor: <条目 ID>` / `references: [...]`）。

**检查点（六拍）**：① 生成参考分配表 → ② 落盘参考链记录 → ③ 分隔 → ④ 呈出 → ⑤ 出四选项 → ⑥ 等响应。四选项同第 1 步。

读全并照做本文件 `## 第 5 步 —— 批量生成`。

## 第 5 步 —— 批量生成（源 `steps-m/step-05`）

**先问清**：「变体数要几版——1、3 还是 5？」（源侧三档：`[1]` / `[3]` / `[5]`）

**逐条拼提示词**（`items[].prompt` 一整段，含源侧九件）：风格关键词 → 主体（写清谁 / 什么 / 在做什么）→ 调性 → 光 → **hex 色板**（从令牌取）→ 构图（主体位置 / 留白方向）→ 尺寸与比例 → 关键词串 → 参考附件说明（引用第 4 步的参考链）→ **负向词**（把 `brief.visual` 的禁忌逐条写进来）。

**批内锚图先行**：锚图批准后**链式推进**（每张带锚图或上一张作参考），偏离的立刻回退（别攒到最后一起返工）。

**三个服务分支**（**本技能全部落地在本地或导出**）：`[E]` 导出到 `assets/images/prompts/`（**默认档**，裁定 6）｜ `[U]` 上传既有（用户手上已有图——**跳过生成、只登记路径**）｜ `[G]` 服务生成 → **本技能不做**（不接外部服务，用户自行在外生成后回填）。

**产出键**：`items[].prompt` / `prompt_lang`；`prompts[]` 追加 `{id, activity: AS-05, target, file: assets/images/prompts/<name>.md, exported: false}`。

**检查点（六拍）**：① 生成提示词与锚图 → ② 落盘 `prompt` / `prompts[]` / 提示词文件 → ③ 分隔 → ④ 呈出 → ⑤ 出四选项 → ⑥ 等响应。四选项同第 1 步。

## 第 6 步 —— 成套评审（源 `steps-m/step-06`）

**先问清**：「（生成件放进来后）这批图哪几张要重出？」

**批内一致五查**（源侧原口径）：色温 / 光向 / 细节量 / 风格 / **无异批感**（两张放一起像不像同一天拍的）。

**品牌对齐四查**：色协调（与令牌）｜ 调性（与 `brief.visual`）｜ 题材（无禁忌题材）｜ **无文字伪影**（图上不该有写错的字——AI 生成最常见的翻车点）。

**技术质量四查**：分辨率（够不够目标尺寸的 2 倍）｜ AI 伪影（手指 / 接缝 / 重复纹理）｜ 边缘（抠图干净）｜ 压缩友好（渐变不出现色带）。

**文化敏感度**（源侧原口径，**需人工判定**）：人物 / 手势 / 符号在目标市场是否得体——**引擎不核这一条，必须人来判**。

**分支**：`[A]` 全批通过 ｜ `[R]` 重生指定 ｜ `[V]` 出变体 ｜ `[E]` 描述式编辑（「把背景调暗一档」这类）｜ `[T]` 批次调色 ｜ `[C]` 页面场景预览。

**落盘口径**：按类型子目录落 `{output_dir}/assets/images/`（如 `assets/images/heroes/`）；**原始提示词随产物留档**（源侧口径——写进 `prompts[]` 的 `file`）；`items[].assets[].path` 存相对路径。
**已知缺口（登记）**：`viewer.py` 只扫顶层 `*.yaml` → `assets/images/` 下的图片**渲染不到**。

**产出键**：`items[].assets[]` + `items[].review`（批内五查 + 品牌四查 + 技术四查 + 文化敏感度）+ `activities[AS-05].status: 已评审`。

**收尾动作**：更新活动级 `status` 到 `已评审`；一句话说明图片是页面稿的上游料（第 2 步的就绪度评估会回读这批）；本文件到此结束——读 `steps/06-motion.md` 继续，或回活动菜单。

**检查点（六拍）**：① 生成评审表 → ② 落盘 `assets` / `review` / 活动 `status` → ③ 分隔 → ④ 呈出 → ⑤ 出四选项 → ⑥ 等响应。四选项同第 1 步。
