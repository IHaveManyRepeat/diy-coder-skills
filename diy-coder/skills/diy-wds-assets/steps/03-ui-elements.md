# Step 3 — UI 元素（U）

Progress: `[1 载组件上下文] → [2 态×变体矩阵] → [3 渲染方式] → [4 按组件组生成] → [5 合规与无障碍评审]`

**Read (input):** `{output_dir}/wds-design-system.yaml` 的**组件定义**（按钮变体 / 卡片 / 表单 / 导航 / 反馈）与**渲染相关令牌**（分态色 / 字 / 间距 / 边框 / 阴影 / 过渡）；`{output_dir}/wds-scenarios.yaml` 的 `scenarios[].pages[]`（组件用在哪些页）；`{output_dir}/assets/ui-elements/` 既有件（自产回读）。
**Write (output):** `wds-assets.yaml` 的 `activities[AS-03]`；`{output_dir}/assets/ui-elements/` 与 `prompts/`。

你是 **UI 件生产的主持人**（源 `steps-u/` 五步）。UI 件回答的是**一个组件长什么样、五个态各是什么样**——它**不读风格库**（源侧口径）：风格由设计系统令牌定死，审美在这个活动里不是变量，**一致性才是**。

**本段纪律**：① **5 态固定**（`default` / `hover` / `focus` / `active` / `disabled`），少一个不算完（源侧原话）；② **不接外部服务**（裁定 6）——产出提示词与 HTML/CSS；③ **无障碍是本活动的硬门**（第 5 步 WCAG AA）——不是可选项。

## 第 1 步 —— 载组件上下文（源 `steps-u/step-01`）

**先问清**：「这批要做哪些组件？」——先按设计系统的组件定义列出候选，别凭记忆报名字。

**读两样**：
1. **组件定义**——`wds-design-system.yaml` 的组件段：按类分组（按钮 / 输入 / 卡片 / 导航 / 反馈），每组的变体清单（`primary` / `secondary` / `ghost`…）；
2. **渲染相关令牌**——**分态色**（`default` / `hover` / `focus` / `active` / `disabled` 各态的背景 / 边框 / 文字色）、字号 / 间距 / 边框宽 / 阴影层级 / 过渡时长。

**五态是常量**：`[default, hover, focus, active, disabled]`——写进每条 `items[].state`。**不读 `data/styles/`**（源侧口径：UI 件的风格由令牌决定，风格库在这一步只会造成漂移）。

**产出键**：`activities[AS-03].status: 进行中` + `stage: UI件`；上下文摘要会话内呈出。

**检查点（六拍）**：① 生成摘要 → ② 落盘活动 `status` / `stage` → ③ 分隔 → ④ 呈出 → ⑤ 出四选项 → ⑥ 等响应。
`[a]` 高级引导 → 调 `diy-elicit`（零写面）｜ `[c]` 继续 → 进下一步 ｜ `[p]` 多方模式 → 调 `diy-party-mode`（零写面）｜ `[y]` YOLO → 跳过后续检查点连续推进（首次选中时一行明示）。

## 第 2 步 —— 态×变体矩阵（源 `steps-u/step-02`）

**先问清**：「全做、只做高频的，还是点名几个？」

**打出矩阵**：`组件 × 变体 × 态`——每格一条资产（源侧口径）。矩阵的行数与格数是**算出来的**，不是估的：把总数写进呈出表（「5 组件 × 3 变体 × 5 态 = 75 格」这类）。

**优先级三档**（源侧原话，写进 `items[].variant` 的备注或 `spec`）：
- `H` **每页都用**（按钮、链接、输入框）——先做；
- `M` **多页用**（卡片、标签）；
- `L` **专页用**（某个页面特有的人造件）——最后做或不做。

**范围四选一**（写进 `activities[AS-03].scope`）：`all` / `priority`（只做 H）/ `select`（点名）/ `category`（按组件类）。

**去重**：同名同变体同态的格**只留一条**（矩阵天然去重），带 `state` 数组的条目按态拆成独立格。

**产出键**：`activities[AS-03].items[]`（`id: AS-03.<m>` 递增；`name` / `state` / `variant` / `size` / `spec` 非空）。

**检查点（六拍）**：① 生成矩阵表（含合计数）→ ② 落盘 `items[]` / `scope` → ③ 分隔 → ④ 呈出 → ⑤ 出四选项 → ⑥ 等响应。四选项同第 1 步。

读全并照做本文件 `## 第 3 步 —— 渲染方式`。

## 第 3 步 —— 渲染方式（源 `steps-u/step-03`）

**先问清**：「这批 UI 件要矢量感、写实感，还是纯平面？」

**渲染方式三选一**（源侧原口径，写进 `activities[AS-03].style`）：
| 值 | 含义 |
| --- | --- |
| `V` Vector CSS | 矢量风：纯 CSS 画（圆角 / 描边 / 阴影都从令牌取） |
| `R` Realistic | 写实感：带材质与光影（适合拟物按钮 / 立体卡片） |
| `F` Flat | 纯平面：零阴影零渐变 |

**态的呈现方式三选一**：`G` Grid（**一变体的全态排在一张图上**——批量最快）｜ `I` Individual（**一资产一提示词 + 参考链**——质量最高）｜ `A` Animated（态之间要动画过渡）。

**令牌映射**：逐条 `items[].token_ref` 写清这条压哪些令牌键（态色 / 边框 / 阴影 / 过渡）。**渲染方式与令牌冲突时令牌赢**（源侧「令牌是唯一风格源」的同一条纪律）。

**批量策略**（源侧口径）：`Grid` 模式下一变体全态共用一段提示词；`Individual` 模式下每格一段提示词 + 前一格作参考。

**产出键**：`activities[AS-03].style`（`design` 记渲染方式码，`content` 留空）+ `items[].token_ref`。

**检查点（六拍）**：① 生成渲染方式与映射表 → ② 落盘 `style` / `token_ref` → ③ 分隔 → ④ 呈出 → ⑤ 出四选项 → ⑥ 等响应。四选项同第 1 步。

读全并照做本文件 `## 第 4 步 —— 按组件组生成`。

## 第 4 步 —— 按组件组生成（源 `steps-u/step-04`）

**先问清**：「组件组的顺序按源侧约定走（按钮 → 表单 → 卡片 → 导航 → 反馈），还是要调整？」——**默认按此序**：先做被引用最多的组，后面各组能拿前面的件作参考。

**逐条拼提示词**（`items[].prompt` 一整段）：组件名 + 变体 + **态**（写清这一格的态是什么：底色 / 边框 / 文字 / 阴影怎么变）→ 尺寸（按令牌的控件高度与内边距）→ 令牌值（色逐值写明用途）→ 渲染方式关键词（`V`/`R`/`F` 对应的描述）→ 输出要求（HTML/CSS 优先；SVG 兜底）。

**批量策略落地**：`Grid` 模式一条提示词出全态排图；`Individual` 模式一格一条 + 链上参考（前一件作参考）。

**逐组批准**：一组做完呈一次，批准后这一组作下一组的参考。

**产出键**：`items[].prompt` / `prompt_lang`；`prompts[]` 追加 `{id, activity: AS-03, target, file: assets/ui-elements/prompts/<name>.md, exported: false}`。

**检查点（六拍）**：① 生成提示词 → ② 落盘 `prompt` / `prompts[]` / 提示词文件 → ③ 分隔 → ④ 呈出 → ⑤ 出四选项 → ⑥ 等响应。四选项同第 1 步。

读全并照做本文件 `## 第 5 步 —— 合规与无障碍评审`。

## 第 5 步 —— 合规与无障碍评审（源 `steps-u/step-05`）

**先问清**：「（生成件放进来后）哪些组件要返工？」

**设计系统合规六查**（源侧原口径）：态色用令牌 ｜ 字号用令牌 ｜ 间距用令牌 ｜ 圆角用令牌 ｜ 阴影用令牌 ｜ 过渡时长用令牌——**六项逐条过**，任一项出现令牌外的值 = 不合规。

**跨组件一致五查**：视觉重量 / 色用法 / 圆角 / 阴影层级 / 禁用态——五样跨组件必须同族（按钮与输入框的圆角不能一个 4px 一个 8px）。

**无障碍硬门（WCAG AA，源侧原口径）**：
- [ ] **正文对比度 ≥ 4.5:1**（用实际色值算，不靠眼估）
- [ ] **大字对比度 ≥ 3:1**（18pt 以上或 14pt 粗体）
- [ ] **焦点可见**——`focus` 态必须有可辨认的焦点指示（且不能只靠颜色差）
- [ ] **禁用态不靠纯降低不透明度**——对比度仍要够看

**四个分支**：`[A]` 全批通过 ｜ `[R]` 重生指定 ｜ `[T]` 调令牌重生（回第 3 步，**这条往往意味着设计系统的令牌该改**——改令牌归 `diy-wds-system`，本技能只登记建议到 `revisions`）｜ `[C]` 对比视图。

**落盘口径**：产物按类型分目录落 `{output_dir}/assets/ui-elements/`（如 `assets/ui-elements/buttons/`）；`items[].assets[].path` 存相对路径。
**已知缺口（登记）**：`viewer.py` 只扫顶层 `*.yaml` → `assets/ui-elements/` 下的产物**渲染不到**。

**产出键**：`items[].assets[]` + `items[].review`（合规六查 + 跨组件五查 + WCAG 四项）+ `activities[AS-03].status: 已评审`。

**收尾动作**：更新活动级 `status` 到 `已评审`；一句话说明 UI 件是页面稿的下游补件（页面稿里缺的组件回这里补）；本文件到此结束——读 `steps/04-icons.md` 继续，或回活动菜单。

**检查点（六拍）**：① 生成评审表（含对比度实测值）→ ② 落盘 `assets` / `review` / 活动 `status` → ③ 分隔 → ④ 呈出 → ⑤ 出四选项 → ⑥ 等响应。四选项同第 1 步。
