# Step 1 — 线框（W）

Progress: `[1 载上下文] → [2 资产盘点] → [3 选风格与保真度] → [4 生成提示词] → [5 成套评审]`

**Read (input):** `{output_dir}/wds-scenarios.yaml` 的 `scenarios[].pages[]`（`id` / `name` / `purpose`——本活动的**唯一规格源**）；`{output_dir}/wds-design-system.yaml`（可选：布局令牌 `grid` / `spacing` / `breakpoints` / `container`）；`{output_dir}/assets/wireframes/` 既有产物（自产回读，防重复）；`data/styles/design-styles/` 目录（只读目录列候选，不预载卡片内容）。
**Write (output):** `wds-assets.yaml` 的 `activities[AS-01]`（`scope` / `style` / `items[]`）+ 各条的 `prompt`；`{output_dir}/assets/wireframes/` 下的产物与 `prompts/`。

你是**线框生产的主持人**（源 `steps-w/` 五步）。线框回答的是**结构**问题——哪块内容在哪、页面怎么排、断点怎么塌，**不回答长相**（那是页面稿的事）。

**本段纪律**：① **每条资产都必须挂到某个 `SC-<nn>.P<n>`**——挂不上的条目不许进 `items[]`（源侧「Specification-Driven」原则）；② **本技能不接外部服务**（裁定 6）——第 4 步产出的是**可粘贴的提示词**，不是位图；产物 **HTML 优先**（用户拍板）；③ 上下文摘要与盘点表**先呈批再往下**。

## 第 1 步 —— 载上下文（源 `steps-w/step-01`）

**先问清**：「这一轮要给哪几页画线框？你手上有没有已经画过的？」源侧这一步只做一件事——**把要用的输入全部读出来再开口**。

**读三样，读不全就别往下**：
1. **页面规格**——`wds-scenarios.yaml` 的 `scenarios[].pages[]`：页名 / 目的 / 入口情境 / 离页动作 / 页内交互（这是结构的来源）；
2. **设计系统布局令牌**——`wds-design-system.yaml`：栅格（列 / 沟槽 / 边距）、间距阶、断点定义、容器宽。**可选读**：产物缺失时降级为「按 `brief.visual.visual_direction` 口头约定」并在收尾记 gap（`token_ref` 留空）；
3. **既有线框**——扫 `{output_dir}/assets/wireframes/`：已存在的页 / 已批准的参考件 / 过期的件（按 `wds-assets.yaml` 的 `AS-01` 条目对表，别重画）。

**产出键**：`activities[AS-01].style.design` 先留空；把上下文摘要写进会话（**不落盘**）。

**呈出上下文摘要**（会话内，六拍的第 ④ 拍）：页面清单 / 栅格 / 断点 / 既有件数——**四样都要有具体值**，写「按规格」等于没写。

**检查点（六拍）**：① 生成摘要 → ② 落盘（`AS-01.status: 进行中` + `stage: 线框`）→ ③ 分隔 → ④ 呈出摘要 → ⑤ 出四选项 → ⑥ 等响应。
`[a]` 高级引导 → 调 `diy-elicit`（零写面）｜ `[c]` 继续 → 进下一步 ｜ `[p]` 多方模式 → 调 `diy-party-mode`（零写面）｜ `[y]` YOLO → 跳过后续检查点连续推进（首次选中时一行明示）。

读全并照做本文件 `## 第 2 步 —— 资产盘点`。

## 第 2 步 —— 资产盘点（源 `steps-w/step-02`）

**先问清**：「这次是全做、挑几页做，还是只补缺的？」**范围必须由用户选**，不自作主张。

**盘出「页 × 视图」清单**：每页 Desktop / Mobile 两个视图各一条（源侧口径），逐条标 `H/M/L` 优先级（H = 关键路径页）。**跨引既有**：命中的标 `已存在`、规格变了的标 `过期`，两者都不进本轮生成。

**范围三选一**（写进 `activities[AS-01].scope`）：`all`（全做）/ `select`（用户点名几页）/ `missing`（只补缺的）。**范围之外的页不要偷偷塞回来**。

**产出键**：`activities[AS-01].items[]` 铸条目（`id: AS-01.<m>` 两位序号递增；`name` / `pages` / `size` / `spec` 四键非空），`status: 进行中`。**铸号由引擎核**（父子同源、不重号）。

**收尾动作**：呈出盘点表（页 / 视图 / 优先级 / 既有一列）并等用户点头。

**检查点（六拍）**：① 生成盘点表 → ② 落盘 `items[]` + `scope` → ③ 分隔 → ④ 呈出 → ⑤ 出四选项 → ⑥ 等响应。四选项同第 1 步。

读全并照做本文件 `## 第 3 步 —— 选风格与保真度`。

## 第 3 步 —— 选风格与保真度（源 `steps-w/step-03`）

**先问清**：「这批线框要画到多细——只画框，还是带真实文案和标注？」

**保真度三档**（源侧原话，写进 `items[].variant`）：
| 档 | 画到什么 |
| --- | --- |
| `L` Low-Fi | 只画块与位置，不写内容 |
| `M` Mid-Fi | 结构 + 内容占位（真文案可选） |
| `H` High-Fi | 结构 + 真文案 + 间距标注 |

**设计风格**：读 `data/styles/design-styles/` **目录**（6 张卡：`brutalist` / `corporate` / `editorial` / `minimal` / `organic` / `playful`），按名列出候选让用户挑一张，取该卡的 `Prompt Keywords` 拼进提示词。写进 `activities[AS-01].style.design`。**风格影响的是「间距感与布局原则」，不是配色**——线框阶段说「我们走 Minimal」是在说留白大方、描边细。

**标注开关**：`[Y]` 要标注（尺寸 / 间距 / 断点）或 `[N]` 不要，写进 `items[].review.checks` 的备注。

**产出键**：`activities[AS-01].style`（`design` 必填、`content` 留空——线框不读 content-styles）+ `items[].variant` / `size`（`"1440x900"` / `"390x844"` 形态）。

**检查点（六拍）**：① 生成选择表 → ② 落盘 `style` / `variant` / `size` → ③ 分隔 → ④ 呈出 → ⑤ 出四选项 → ⑥ 等响应。四选项同第 1 步。

读全并照做本文件 `## 第 4 步 —— 生成提示词`。

## 第 4 步 —— 生成提示词（源 `steps-w/step-04`）

**先问清**：「提示词你打算导出去用哪件工具？」——**问的只是提示词的收件人**（用来定 `target`），不是要连它（裁定 6）。

**逐条拼提示词**（每条 `items[].prompt` 一段整块，可整段粘贴）：
1. **保真度**：`L/M/H` 决定写到多细；
2. **栅格与断点**：列 / 沟槽 / 边距 / 容器宽（来自第 1 步读到的布局令牌）；
3. **内容区**：按页面规格的结构写（头部 / 主区 / 侧栏 / 尾部的顺序与约略高度比）；
4. **风格关键词**：第 3 步选中卡的 `Prompt Keywords`（**逐词保留英文**——把它们翻成中文会给生成服务喂错语言）；
5. **尺寸**：`1440x900` / `390x844`；
6. **灰度色板**：线框阶段用灰阶（`#FFFFFF` / `#F5F5F5` / `#D9D9D9` / `#8C8C8C` / `#262626`）；
7. **标注**：`[Y]` 时写明标注哪些（尺寸 / 间距 / 断点），`[N]` 时写「no annotations」。

**逐页批准**：一条一条呈出，用户点头的才推进下一条；**已批准的桌面件作为同页移动件的参考**（源侧「先桌面后移动」的落地方式）。

**产出键**：`items[].prompt`（非空、整段）+ `items[].prompt_lang`（`en` / `zh`）+ `prompts[]` 追加一条 `{id: <条目 ID>, activity: AS-01, target: <用户说的收件人>, file: assets/wireframes/prompts/<name>.md, exported: false}`。

**收尾动作**：把本轮提示词**落成文件**到 `{output_dir}/assets/wireframes/prompts/`（HTML 优先的产物形态下，这一份 md 是**唯一的生成入口**），并告诉用户「拿去生成、回来把产物放 `assets/wireframes/`」。

**检查点（六拍）**：① 生成提示词 → ② 落盘 `prompt` / `prompts[]` / 提示词文件 → ③ 分隔 → ④ 呈出 → ⑤ 出四选项 → ⑥ 等响应。四选项同第 1 步。

读全并照做本文件 `## 第 5 步 —— 成套评审`。

## 第 5 步 —— 成套评审（源 `steps-w/step-05`）

**先问清**：「（把生成件放进来后）这批线框你要整批通过，还是挑几张重生？」

**一致性四查**（源侧原口径，逐条过）：
- [ ] **栅格**：各页列数 / 沟槽 / 边距同值（跨页漂移即不一致）
- [ ] **导航**：同一层级的导航结构在各页位置一致
- [ ] **字阶**：标题 / 正文的层级关系一致（线框阶段看的是**大小关系**不是字体）
- [ ] **间距**：同类型区块的间距同阶（不是逐个目测）

**三个分支**：`[A]` 全批通过 → 逐条写 `review.verdict: 通过`；`[R]` 重生指定 → 回第 4 步改提示词重出；`[S]` 调风格重生全部 → 回第 3 步换卡。

**落盘口径**：产物落 `{output_dir}/assets/wireframes/`（**子目录、不入库**，裁定 12）；YAML 里**只登记路径引用**（`items[].assets[].path = assets/wireframes/<name>.html`，`format: html`）。
**已知缺口（登记）**：`viewer.py` 只扫 `output_dir` 顶层 `*.yaml` → **`assets/` 下的产物渲染不到**；线框的评审结论只在 `wds-assets.yaml` 里可见，产物本身要点开文件看。

**产出键**：`items[].assets[]`（路径引用）+ `items[].review`（`checks` 四项结论 + `verdict`）+ `activities[AS-01].status: 已评审`。

**收尾动作**：更新活动级 `status` 到 `已评审`，一句话说明「线框完成后通常接着做页面稿；页面稿的就绪度评估会回读这批 `assets/wireframes/`」；本文件到此结束——读 `steps/02-page-designs.md` 继续，或回活动菜单换一个活动。

**检查点（六拍）**：① 生成评审表 → ② 落盘 `assets` / `review` / 活动 `status` → ③ 分隔 → ④ 呈出 → ⑤ 出四选项 → ⑥ 等响应。四选项同第 1 步。
