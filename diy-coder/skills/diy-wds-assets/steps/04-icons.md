# Step 4 — 图标（I）

Progress: `[1 载图标上下文] → [2 盘点与去重] → [3 图标风格] → [4 分组生成与后处理] → [5 一致性与隐喻评审]`

**Read (input):** `{output_dir}/wds-scenarios.yaml` 的 `scenarios[].pages[]` + **页内交互**（图标引用的来源）；`{output_dir}/wds-design-system.yaml` 的**图标令牌**（尺寸 / 描边宽 / 单色多色 / 容器）；`{output_dir}/assets/icons/` 既有件 + 外部图标库引用（源侧口径允许匹配开源图标库，**本技能不代下载**，只登记引用）。
**Write (output):** `wds-assets.yaml` 的 `activities[AS-04]`；`{output_dir}/assets/icons/` 与 `prompts/`。

你是**图标集生产的主持人**（源 `steps-i/` 五步）。图标是**一套**不是一堆——每个图标单看都对、放一起不像一家，就是失败。它**不读风格库**（源侧口径）：形状语言由图标令牌定。

**本段纪律**：① **先分类再去重**（源侧口径）——跨页同义图标合并、尺寸变体不重复计；② **不接外部服务**（裁定 6）——产出 SVG/HTML 与提示词；③ **隐喻清晰度是本活动独有的评审项**（源侧原口径，别省）。

## 第 1 步 —— 载图标上下文（源 `steps-i/step-01`）

**先问清**：「这批图标要覆盖哪些页？」

**读三样**：
1. **图标引用**——从 `scenarios[].pages[]` 的页内交互与页面结构里**逐条抽**图标需求，按源侧六类归：**导航 / 动作 / 状态 / 分类特性 / 社交 / 装饰**；
2. **图标令牌**——尺寸四档 `sm 16` / `md 24` / `lg 32` / `xl 48`（px）、描边宽、单色 / 多色、是否需要容器（圆形底 / 方形底）；
3. **既有件**——扫 `{output_dir}/assets/icons/`；外部图标库引用只**登记**（源侧 `[L]` 分支），**本技能不去下载、不调任何库服务**。

**产出键**：`activities[AS-04].status: 进行中` + `stage: 图标`；上下文摘要会话内呈出（含六类各自的条数）。

**检查点（六拍）**：① 生成摘要 → ② 落盘活动 `status` / `stage` → ③ 分隔 → ④ 呈出 → ⑤ 出四选项 → ⑥ 等响应。
`[a]` 高级引导 → 调 `diy-elicit`（零写面）｜ `[c]` 继续 → 进下一步 ｜ `[p]` 多方模式 → 调 `diy-party-mode`（零写面）｜ `[y]` YOLO → 跳过后续检查点连续推进（首次选中时一行明示）。

读全并照做本文件 `## 第 2 步 —— 盘点与去重`。

## 第 2 步 —— 盘点与去重（源 `steps-i/step-02`）

**先问清**：「全做、按类做、逐个挑，还是先做导航与动作这两类？」

**图标目录表**：逐条写 **名 / 类 / 用在哪些页 / 所需尺寸**（四列齐）。

**去重三刀**（源侧原口径，这是本步的核心动作）：
1. **跨页合并**——两页都用「搜索」，是**一个**图标不是两个（`pages` 数组列全）；
2. **尺寸变体**——同一图标要 16 与 24 两档时，**一条条目挂两个尺寸**（`size` 写 `"16,24"`），不拆成两条；
3. **可共享底形**——同一底形的（如圆形底 + 内符）合并为一组生成，底形只做一次。

**批量规模估计**：写出去重前后的条数（「抽到 42 条 → 去重后 28 条」），这个差就是这一步省下的工作量。

**范围四选一**（写进 `activities[AS-04].scope`）：`all` / `category`（按类）/ `select`（点名）/ `priority`（**导航 + 动作**两类——源侧建议的起手式）。

**产出键**：`activities[AS-04].items[]`（`id: AS-04.<m>` 递增；`name` / `pages` / `variant`（类）/ `size` / `spec` 非空）。

**检查点（六拍）**：① 生成索引表（含去重前后计数）→ ② 落盘 `items[]` / `scope` → ③ 分隔 → ④ 呈出 → ⑤ 出四选项 → ⑥ 等响应。四选项同第 1 步。

读全并照做本文件 `## 第 3 步 —— 图标风格`。

## 第 3 步 —— 图标风格（源 `steps-i/step-03`）

**先问清**：「图标走线描、实心、双色，还是字符式？」

**图标风格四选一**（源侧原口径，写进 `activities[AS-04].style.design`）：`O` Outline（线描）/ `F` Filled（实心）/ `D` Duotone（双色）/ `G` Glyph（字符式）。

**细化参数**（源侧口径，逐项定死再开工）：
- **描边宽**（如 `1.5px`）与**端点 / 转角**（圆头 or 方头）；
- **网格**：`24×24` 含 `2px` 内边距 = **`20×20` 活区**（所有图标都在这条格里画，这样视觉重量才一致）；
- **颜色处理三选一**：`M` `currentColor`（跟随文字色，最省）/ `B` 品牌色（用令牌里的主色）/ `F` 固定色；
- **输出格式**：**SVG 为主，PNG 兜底**（源侧口径）。

**产出键**：`activities[AS-04].style`（`design` = 风格码 + 细化参数写进 `spec`）+ `items[].size` / `items[].token_ref`。

**检查点（六拍）**：① 生成风格参数表 → ② 落盘 `style` / `size` / `token_ref` → ③ 分隔 → ④ 呈出 → ⑤ 出四选项 → ⑥ 等响应。四选项同第 1 步。

读全并照做本文件 `## 第 4 步 —— 分组生成与后处理`。

## 第 4 步 —— 分组生成与后处理（源 `steps-i/step-04`）

**先问清**：「五组按源侧顺序做（导航 → 动作 → 状态 → 特性 → 社交），还是先做某一组？」

**逐组做，组内首件批准后作参考**（源侧原口径，这是批量一致的机制）：组内第一件经用户批准 → 作为同组后续图标的参考件 → 偏离参考的重新出。

**逐条拼提示词**（`items[].prompt` 一整段）：图标名与含义 → 类与风格码 → 网格与活区（`24×24` / 活区 `20×20`）→ 描边宽与端点 → 颜色处理 → 尺寸 → 输出格式（SVG 优先）。

**SVG 后处理四步**（源侧原口径，**生成回来的 SVG 必须过这一道**）：① 清 markup（去掉编辑器留下的 `<defs>` / 无用 id / 注释）；② 校 `viewBox`（统一 `0 0 24 24`）；③ 单色图标设 `currentColor`（双色保留两色但两色都走令牌）；④ 像素对齐（`0.5px` 偏移会让描边发虚）。

**产出键**：`items[].prompt` / `prompt_lang`；`prompts[]` 追加 `{id, activity: AS-04, target, file: assets/icons/prompts/<name>.md, exported: false}`。

**检查点（六拍）**：① 生成提示词与后处理日志 → ② 落盘 `prompt` / `prompts[]` / 提示词文件 → ③ 分隔 → ④ 呈出 → ⑤ 出四选项 → ⑥ 等响应。四选项同第 1 步。

## 第 5 步 —— 一致性与隐喻评审（源 `steps-i/step-05`）

**先问清**：「（生成件放进来后）图标集里哪些要重画？」

**一致性六查**（源侧原口径）：描边宽 ｜ 视觉重量 ｜ 圆角 ｜ 细节层级 ｜ 内边距 ｜ **最小尺寸可辨**（缩到 16px 还认得出吗——这条一定要真缩着看）。

**隐喻清晰度三查**（**本活动独有**，源侧原口径）：
- [ ] **含义明确**——不看标签也能猜出它是什么意思；
- [ ] **不混**——与相近图标（如「设置」齿轮与「配置」滑杆）不会看错；
- [ ] **文化适配**——跨文化不产生歧义（手势、动物、颜色象征）。

**分支**：`[A]` 全批通过 ｜ `[R]` 重生指定 ｜ `[W]` **全局调描边**（回第 3 步改描边宽，**全组重出**）｜ `[S]` 最小尺寸测试 ｜ `[C]` UI 场景预览（放进实际页面看）。

**尺寸变体**：批准的图标出多档尺寸（SVG 为主 + PNG `1x` / `2x` / `3x` 兜底），落 `{output_dir}/assets/icons/svg/` 与 `assets/icons/png/`。

**落盘口径**：`items[].assets[].path = assets/icons/svg/<name>.svg`。
**已知缺口（登记）**：`viewer.py` 只扫顶层 `*.yaml` → `assets/icons/` 下的图标**渲染不到**（评审结论只在 `wds-assets.yaml` 里）。

**产出键**：`items[].assets[]` + `items[].review`（一致性六查 + 隐喻三查 + `verdict`）+ `activities[AS-04].status: 已评审`。

**收尾动作**：更新活动级 `status` 到 `已评审`；一句话说明图标是页面稿的下游补件；本文件到此结束——读 `steps/05-images.md` 继续，或回活动菜单。

**检查点（六拍）**：① 生成评审表 → ② 落盘 `assets` / `review` / 活动 `status` → ③ 分隔 → ④ 呈出 → ⑤ 出四选项 → ⑥ 等响应。四选项同第 1 步。
