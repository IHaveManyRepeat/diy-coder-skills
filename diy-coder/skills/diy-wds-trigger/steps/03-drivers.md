## 第 1 步 —— 驱动因素与跨群模式（源 step-04）

**先说清为什么**：讲清「两面都要问」——正向 = 想要达成 / 得到 / 体验的；负向 = 想避免 / 逃离 / 防住的。用你自己的话讲，别照读。

**引导问句（源 `step-04:89-135`，逐群问完再问下一群）**：

- **正向**：「**{人物名} 想达成或体验到什么？**」提示——什么会让他这一天更好过？什么会让他跟同事炫耀？什么会让他觉得自己成功了？
- **负向**：「**{人物名} 想躲开或逃离什么？**」提示——什么让他夜里睡不着？什么烦他烦了很久？什么风险让他不安？什么丢脸事他想避免？
- **每条补三样**（源 `templates/persona-document.template.md:160-206`）：**正向** = 描述 + 为什么重要 + 成功长相 + **`[Product] Promise`**（产品怎么兑现它）；**负向** = 描述 + 为什么可怕 + 失败长相 + **`[Product] Answer`**（产品怎么挡住它）。**「为什么重要」与 Promise/Answer 都要具体、可用**，不写「希望它好用」这类空话。

**量纲（裁定 6，取采集端较宽侧）**：**每人正向 3–5 条 + 负向 3–5 条**。源侧展示端硬编码「exactly 3」与采集端「3–5」互斥——本批取 3–5，展示端按 N 条自适应（`05-documents.md` 的节点模板因此写成 N 条可扩展）。

**产出键**：

- `personas[].driving_forces.positive[]`：`{id: DF-<n>.<m>+, statement, why, success_looks_like, promise}`——`<n>` = 人物序号（与 `TG-<n>` 同号）、`<m>` 从 1 起；**按优先级降序排列**（下游 `diy-wds-scenarios` 读前 3 条作 Top 3）。
- `personas[].driving_forces.negative[]`：`{id: DF-<n>.<m>-, statement, why, failure_looks_like, answer}`——同上。
- **`driving_forces` 嵌在人物内，不设与 `personas[]` 并列的顶层 `driving_forces[]`**（裁定 16：承诺文案与人物绑定，顶层再放一份 = 同一信息两处写）。

**跨群模式（源 `step-04:124-135`，四个工作坊的第三个产出）**：全部人物问完后，横着看一遍，落 `driver_patterns`：

```
共（shared）  —— 多群都在意的，列 ids
独（unique）  —— 只有某一群在意的，列 id
张力（tensions）—— 两群互相冲突的（例：一群要快、一群要准）；没有就留空列表
```

每条带 `note` 说清「为什么算共 / 算独 / 算张力」。**引用的驱动因素 ID 必须能在产物里解析**（`check` 报 `UNKNOWN_ID`）。

**用户关卡**：逐群念「Wants / Avoids」两栏，问「**这两面都抓到了吗？**」；跨群模式念一遍，问「共 / 独 / 张力的分法你认吗？」

## 第 2 步 —— 优先级与焦点声明（源 step-05）

**先说清为什么**：讲清「为什么必须做取舍」——**焦点就是敢对一部分东西说「还不」**；没有取舍，设计注意力会被摊平。用你自己的话讲。

**引导问句（源 `step-05:71-130`，**每一次排序都要问「为什么」**，不接受「凭感觉」）**：

1. **人物排序**：「**哪一群被伺候好了，对你上面那条主目标影响最大？**」→ 追问「**为什么 {甲} 比 {乙} 更重要？**」（源侧硬规则：`FORBIDDEN to accept prioritization without challenging the reasoning`）。
2. **驱动因素排序**：对**前 2–3 群**逐群问「**这群人最在意的 3–5 条驱动因素是哪些？**」并提醒**负向往往权重更高**（损失厌恶）。
3. **焦点声明**（源 `step-05:109-130`）：「**主群是谁、次群是谁？Must / Should / Could 各是哪些驱动因素？**」——末尾问一句「**这个焦点对吗？它决定后面所有功能判断。**」

**产出键**：

- `priority.ranked_personas`：`[{id: TG-<n>, why}]`——**覆盖全部人物恰一次**；`why` 缺一条就落不下去（源侧硬要求：「每个排序必须给 why」）。
- `priority.ranked_drivers`：`[{id: DF-…, why}]`——**不要求覆盖全部驱动因素**（源侧只排前 2–3 群的），但每条都要 `why`。
- `priority.focus_statement`：`{top_group: TG-<n>, must: [...], should: [...], could: [...]}`——`top_group` **必须 = 排序第一名**（`check` 报 `SET_MISMATCH`）；`must` **非空**（焦点声明必须给必办项）。

**用户关卡**：排序表 + 焦点声明一块念一遍，明确问「**这个取舍你认吗？认了就不再回头改**」——**没点头不落盘**。

**检查点（六拍）**：① 生成 → ② 落盘 `priority` 三段 → ③ 分隔 → ④ 呈出「人物排序 + 驱动排序 + Must/Should/Could」→ ⑤ 出四选项 → ⑥ 等响应。

**收尾与路由**：`priority` 三段经用户点头、`stage: 优先级`，读 `./04-features.md`。本文件到此结束，不再回头。
