# Step 2 — 对齐文档（Alignment）

Progress: `[1 起点] → 2 The Realization → 3 Why It Matters → 4 How We See It Working → 5 Paths We Explored → 6 Recommended Solution → 7 The Path Forward → 8 The Value We'll Create → 9 Cost of Inaction → 10 Our Commitment → 11 Summary → 12 回述合成呈批`

**Read (input):** `./01-intake.md` 的进入回执（骨架已铸、`intake` 分诊结论与 `client_profile` 四域）；用户手上已有的沟通材料（源 01c / 01d 的抽取入口，有才读）；用户在本文件各步的回答。
**Write (output):** `alignment` 段（`status` + 十节）；`intake.stage: 对齐`；给用户的逐步呈出与最终呈批。

你是**对齐的主持人**（源 wds-0-alignment-signoff 的 Phase 1–3）。这一段的目的只有一个：**把「为什么要做」讲成别人能点头的十句话**。资产是叙事的十节框架，不是文书。

**本段纪律**：**十节可换序**（源明示「Flexible order」）——按用户的自然思路走，但**十一节全都要落到键上**，缺哪节回头补。每节都「**keep it brief**」：一节的正文通常是 2–3 句 + 1–2 句证据，不是小作文。

## 第 1 步 —— 起点与既有材料（源 01c / 01d / 01e）

**先说清为什么**：讲清「为什么先问手头有没有现成材料」——已有的邮件 / 提案 / 会议纪要里往往已经有答案，问一遍胜过编十遍。用你自己的话讲。

- **有没有现成材料？**（源 01c 可选增强步）有 → 请用户贴进来或给路径，**只读**抽取：已确认的处境、已提过的方案、已说过的顾虑，逐条落到对应节的候选内容；没有 → 直接进第 2 步，别劝。

## 第 2 步 —— The Realization

**框架**：Problem-Agitate-Solve（源标注的起步框架）。

引导问句（用对话口吻，逐条追问到具体）：
- 你意识到**什么**需要人管一管了？
- 你**观察到**了什么？
- 你看到的**挑战**是什么？
- 你手上有什么**证据**说明这是真的？

**证据要两类都给**（源的最佳实践）：**软证据**（客户的抱怨与表扬、干系人说过什么、反复出现的模式、访谈里的原话）+ **硬证据**（统计数字、分析工具里的曲线、问卷或测试结果、日志与报错）。组合口径：**先软后硬**——软证据让人共情，硬证据让人相信。

**落盘**：`alignment.realization`（2–3 句实情 + 1–2 句证据）。**同一步把方案的种子记下来**（源 02b 的倒序分支：用户从方案入手时，本步负责回头挖出「什么事让你想到它」）。

**检查点（六拍）**：① 生成 → ② 落 `alignment.realization` → ③ 分隔 → ④ 呈出 → ⑤ 出四选项 → ⑥ 等响应。四选项同上步。

## 第 8 步 —— The Value We'll Create

**框架**：Business Case（回报是什么）。

引导问句：**我们的野心是什么**？**做成了会发生什么**？能看到**哪些好处**？**预期结果**是什么？**怎么算成功**？**哪些指标**说明我们在赢？**创造出什么价值**？

**口径**：源侧的最佳实践 = **正向断言 + 成功指标**——「我们有信心它能成」配上「我们会这样量它」，既热又冷。四样都要落到：**野心**（想干成什么）/ **成功指标**（具体可量）/ **成功的样子**（看得见的结果）/ **怎么盯**（一句）。

**落盘**：`alignment.value_we_create`。

**检查点（六拍）**：① 生成 → ② 落键 → ③ 分隔 → ④ 呈出 → ⑤ 出四选项 → ⑥ 等响应。四选项同上步。

## 第 9 步 —— Cost of Inaction

**框架**：PAS 的 Agitate + Business Case。

引导问句：**不做会怎样**？**不动有什么风险**？**会错过什么机会**？**什么都不干的代价**是什么？**拖下去什么会变糟**？**等下去我们失去什么**？

四类代价里挑真的那几条：财务（掉的收入、涨的成本）/ 机会（错过的窗口）/ 竞争（对手拉开距离）/ 运营（低效、问题继续恶化）。

**落盘**：`alignment.cost_of_inaction`——这一节要让人读出「我们耗不起」，而不是「不做也行」。

**检查点（六拍）**：① 生成 → ② 落键 → ③ 分隔 → ④ 呈出 → ⑤ 出四选项 → ⑥ 等响应。四选项同上步。

## 第 12 步 —— 回述、合成与呈批（源 03a / 03b / 03d）

**先说清为什么**：讲清「为什么要在落笔前先回述一遍」——理解错了要在这里抓住，别等到干系人桌上。用你自己的话讲。

1. **回述**（源 03a）：把十节的理解整段讲回给用户听，请其确认或纠正——**用户纠正的每一条都当场改**，改完再问一次「还有哪儿不对」。
2. **合成**（源 03b）：十节齐备且确认无误后，按叙事顺序串成一份可对外的对齐文档（源侧产物名 `pitch`，含十节 + 业务背景 + 下一步）。源侧此处要读一个跨技能的 `pitch.template.md`——**diy 侧不落盘 md，直接落 `alignment` 十键**（单一源：文档由 viewer 由 YAML 渲染，见 `## 收尾`）。
3. **呈批**（源 03d）：把成稿交给用户去给干系人看；**支持迭代**——干系人提意见 → 回来改对应的节 → 再呈。用户的**明确接受**是本段放行的条件；没接受就停在这里，不往下走签核。

**落盘**：`alignment.status: 已定稿`；`intake.stage: 签核`（若用户在第 1 步选了「需要点头」）或直接跳 `核心`。

**检查点（六拍）**：① 生成 → ② 落 `status: 已定稿` + 推进 stage → ③ 分隔 → ④ 呈出十节成稿 → ⑤ 出四选项 → ⑥ 等响应。

**收尾与路由**：

- 不要签核（用户看完对齐就说「够了」）→ `signoff.type: 不签核`，`intake.stage: 核心`，读 `./04-core.md`。
