# Step 2 — 两透镜分析（结构先行）

Progress: `定位与定档 → [两透镜分析] → 落盘与交付`

**Read (input):** `stats` 回执的结构地图；target 全文（md 逐节读、yaml 逐顶层键读，不一次通读）；`--style-guide` 文档（若有）；`{output_dir}/editorial-review.yaml` 的当前记录。
**Write (output):** 记录的 `structure` 槽（`model` / `purpose` / `audience` / `findings` / `estimated_reduction_words` / `meets_length_target`）与 `prose` 槽（`findings`）；`open_questions`。

## A. 结构透镜（先做）

六步按序走，一步不跳：

1. **验证输入** —— step 1 的 `stats` 门禁已做（存在、≥3 词、枚举合法）；这里只需确认结构地图与全文一致（章节数与实际标题对得上）。
2. **理解目的** —— 用 `purpose` / `audience`（缺则从内容推断），一句话写出「本文档为帮 [谁] 达成 [什么] 而存在」，填进记录；按目的 / 读者选**一个**结构模型填 `model`：

   | 模型 | 适用 | 首要检查 |
   | --- | --- | --- |
   | `教程线性` | 教程、操作指南、走查 | 前置条件在动作之前；步骤按依赖顺序；末尾有「完成判据」 |
   | `参考 MECE` | API 文档、术语表、配置参考 | 条目可随机访问；互斥且穷尽；每条同构（同一 schema） |
   | `解释抽象到具体` | 深挖、架构综述、概念指南 | 定义 → 语境 → 实现 / 例子；复杂概念有铺垫 |
   | `任务式 meta-first` | 任务、提示词、系统指令 | 输入与约束先于指令；逻辑与数据分离；执行流显式有序 |
   | `战略金字塔` | PRD、研究报告、提案、决策记录 | 结论 / 建议开篇；支撑分组在下；证据跟论点不领跑 |

3. **结构分析** —— 拿 `stats` 的章节地图逐节问：**这一节直接服务上面的目的吗？**再查：真冗余（同一信息原样出现两次 ≠ 摘要 / 强化）、范围越界（该在别的文档里的内容）、埋没（关键信息藏在深处）、可切 / 可并 / 可移 / 可拆的节。`reader_type: 人类` 时逐项理解辅助（图、摘要、例子、提示框）问一句：它帮读者懂、还是纯占位。
4. **流程分析** —— 读者旅程与用法是否一致；过早细节（读者还不需要时先讲了）；缺失脚手架（复杂概念没有铺垫）；反模式（该内联的 FAQ、该删的附录、逐字复述正文的概述）。`reader_type: 人类` 时另看节奏（留白与视觉变化够不够维持注意力）。
5. **生成建议** —— 每条一个分类，`rationale` 一句说清理由：

   | category | 含义 |
   | --- | --- |
   | `CUT` | 整段删掉 |
   | `MERGE` | 与别节合并 |
   | `MOVE` | 换位置 |
   | `CONDENSE` | 显著压缩 |
   | `QUESTION` | 需作者拍板（拿不准就归这里，不硬下结论） |
   | `PRESERVE` | 看起来可删、实为理解服务——显式保留 |

   每条给 `no`（自 1 起连续；裸键 `no` 照写即可——机器按 YAML 1.1 会把它读成布尔 `False`，引擎两形同读，别为此改字段名或加引号）。`impact_words` 按下一节的估计口径估，`comprehension_note` 只在会伤到理解 / 参与感时写（源纪律：`reader_type: 人类` 时这类削减要显式提示）。给 `length_target` 时判断是否达标，填 `meets_length_target`；没给就写 `未设目标`。
6. **固定格式输出** —— 汇总落 step 3 的交付摘要（本文档摘要 → 建议清单 → 汇总），不在本步提前给成品格式。

`findings` 空是合法结果——结构没毛病就写空列表，别为凑数编建议。

## B. 文风透镜（后做）

1. **校准** —— 先认文风、语气、声音，记下**有意为之**的选择（口语、行话、修辞）——它们要保留。`LLM` 读者：无歧义引用、术语一致、显式结构、去 hedging；`人类` 读者：清晰、流畅、可读、自然递进。
2. **过一遍** —— style_guide 在场先逐条对齐它的要求（它覆盖一切，唯独不覆盖 CONTENT IS SACROSANCT）；跳过代码块、frontmatter、结构标记；只挑**妨碍理解的沟通障碍**，不挑风格偏好。
3. **只在既有结构内修** —— 文风透镜只在现有结构内动手：不重排、不增删、不拆并章节（源原则 "Preserve structure"）；结构该不该动归 A 段，同一处两边都看到时以结构透镜的判决为准。
4. **给建议** —— 每条一条最小干预的修订：`original` 逐字抄原文片段，`revised` 给建议稿，`changes` 一句说清改了什么、为什么。
5. **去重合并** —— 同一问题出现在多处 → **一条**，位置列进 `locations`；相互重叠的修订合并成一条，**不得互相冲突**。
6. **不确定就用问句** —— 拿不准的修订写成「Consider: [建议]?」形态（`revised` 里以问号收尾），或落 `open_questions`。
7. **尊重作者声音** —— 有意为之的风格不「改进」；CONTENT IS SACROSANCT。

## 估计口径（两透镜共用）

`impact_words` 与 `estimated_reduction_words` 用 `stats` 的同一词数口径：**中文字符按 1 词计、西文按空白分词计**。`CUT` / `CONDENSE` 估省下多少、`PRESERVE` 记负数（代价），其余按净变化估；`estimated_reduction_words` = 全部建议被采纳的净削减，逐条 `impact_words` 求和要与之相符（终门机械核对）。

## 落盘时机

结构槽在 A 段走完时整体写进记录（含 `estimated_reduction_words`），文风槽在 B 段走完时写——一次一段，不攒到 step 3。`open_questions` 随手记（拿不准、需作者拍板的），step 3 收尾。
