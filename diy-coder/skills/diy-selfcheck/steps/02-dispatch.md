# Step 2 — 三机制派发（Dispatch）

Progress: `冻结与编排判定 → [三机制派发] → 合并去重分级 → 处置与复扫 → 收口呈核`

**Read (input):** Step 1 的锚点与分片方案；被扫目标；目标点名的参考清单。
**Write (output):** `spec-scan/part-<片名>.md`——每片一个文件，落目标同目录的 `spec-scan/` 子目录。

## 派发纪律

- 每个子代理（或单执行者的每一轮）只领**自己那片**的指令，互不通气——独立命中才有置信度价值。
- 每份片指令必含三句：① 所扫版本锚点（md5 + commit，锚一变全废）；② 「不复用任务书写作侧的任何结论——一切断言亲自验」；③ 产物**直接写 md**（标题 + 逐条 finding：`落点 / 引文 / 问题 / 建议 / 严重度`），禁写长 JSON（B7b 截断教训）。
- 单执行者形态：四轮顺序跑（预演 → 交叉复扫 → 引用核对 → 对抗），每轮换视角、不携带前轮结论。

## 片 A 预演扫描（机制归 diy-spec-scan）

按 diy-spec-scan 的预演纪律执行分片：扮演实现者「照着这份规格动手」，每个单元先写「我第 N 步做 X」的执行计划，凡**必须猜**的决策点记一条 finding（八类歧义：分支无定义 / 术语冲突 / 接口缺口 / 输入不明 / 输出不明 / 时序不明 / 直接矛盾 / 隐含假设；`would_guess` 必填）。**禁读实现代码与产物实例**。机器面：findings 落 `{output_dir}/spec-scan.yaml` 新 `SS-###`（顺序递增、永不复用）——由本片承担铸号与 `check --final` 终门初跑。

## 片 B 引用核对（必读实现）

任务书全部外部断言逐条亲验：`file:line` 行号与内容、技能名 / 产物 ID 可解析、数字断言（计数 / 基线值 / 行数）与出处一致、引文逐字。**必报总数**：`核了 N 条外部引用 / M 条不实`——不报总数覆盖率不可判。M 条不实逐条列（出处 + 实测值 + 差异）。

## 片 C 对抗审查（三层，必读实现与 git 状态）

- **盲猎**：只看结构不看细节——写入原子性 / 回滚 / 重入、写权与读取权字面冲突、时序脱节。
- **边界猎手**：走每条分支路径与边界条件——两可之处、枚举外值、空态。
- **验收审计**：验收项逐条问「可机械执行？谁执行？证据是什么？」——不可机械的验收是假验收。
- **用户拍板贯通三问**（目标承载拍板时必查）：逐项拍板查「哪些技能受影响 / 哪些既有条款要改 / 读写面有没有跟着变」——拍板说 A、条款只覆盖半个 A 是两批实证的高危漏项。
