# Step 1 — 冻结与编排判定（Freeze）

Progress: `[冻结与编排判定] → 三机制派发 → 合并去重分级 → 处置与复扫 → 收口呈核`

**Read (input):** 被扫目标全文；`git status` / `git log -1`（目标所在仓库）。
**Write (output):** 版本锚点与编排表（进对话，随后誊入主产物 `anchor` 区块）；创建 `{output_dir}/selfcheck.yaml`。

## 冻结锚点

1. 记目标 md5（对文件内容算，命令给用户看：`md5sum <目标>`）。记当前 git 状态：工作区干净 → 记 HEAD commit hash；工作区有未提交改动 → 提请用户授权一次**锚点提交**（仅含目标文件；用户拒绝则 md5 单锚、`anchor.commit` 缺省并在区块注明「无 commit 锚」）。
2. 锚点三件套 = md5 + commit + 日期。扫描期间目标冻结——这是扫描结果有效性的唯一凭证。
3. 目标行数与二级标题结构一并记录（下一步分片依据）。

## 编排判定

并行度 ∝ 目标规模（B3–B7 实证，非固定数）：

| 目标规模 | 预演片 | 引用核对 | 对抗审查 | 合计 agent |
| --- | --- | ---: | ---: | ---: |
| ≤150 行 | 1（整本） | 1 | 1 | 3 |
| 150–400 行 | 2（按 § 对半） | 1 | 与引用核对合一 | 3–4 |
| >400 行 | 3–5（按 § 分片） | 1 | 1 | 5–7 |

环境形态判定：有子代理派发工具 → **并行分片形态**（首选）；无 → **单执行者顺序形态**（预演 → 交叉 → 引用核对 → 对抗，四轮照跑），且 `anchor` 区块必须诚实登记「self-preference 偏差未完全隔离，可在外部窗口独立复检」（C·15 先例）。

## 收尾：创建主产物

编排判定落定即创建 `{output_dir}/selfcheck.yaml`：`SC-###` 取号＝既有集合 `max+1`（无文件自 SC-001）、`status: 草稿`，写全 `anchor` 四字段（md5 / commit / exec_form / shards——执行形态与分片数此时才确定），判定写入 `target`（`kind` 四选一 任务书|技能|规格|文档；三阶判据链＝①用户明示照录→②规则表机械判→③模糊档先问人；判错 HALT 重走并 `revisions` 留痕）。

## 判定产出

给用户一行播报：`目标 <名>（N 行 / M 个二级节）已冻结 <md5 前 8 位> @ <commit 前 7 位>；编排 = <形态>（<分片方案>）`。
