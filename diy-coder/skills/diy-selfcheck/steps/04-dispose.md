# Step 4 — 处置与复扫（Dispose）

Progress: `冻结与编排判定 → 三机制派发 → 合并去重分级 → [处置与复扫] → 收口呈核`

**Read (input):** A 部分分级表；被扫目标（此刻起允许改）。
**Write (output):** D 表处置记录；改后目标；增量补扫与复扫结果。

## D 表处置

逐条处置，**无处置记录 = 扫描未闭环**：

- **采纳** → 改目标（给 diff 落点：`§N / 行号 + 改前 → 改后`）；牵连条款同步改——先查同一事实在目标里还有几处，一次改尽。
- **驳回** → 写明理由（哪条已写条款覆盖、为什么不是同一层面）；驳回不是忽略，理由进 D 表。
- **观察** → 留档不处置，D 表记去向（进报告观察节 / 汇入机制改进清单）。

D 表列：`# / 级 / 处置 / 落点或理由`。呈核前 D 表无空行。

## 增量补扫

处置落地后按**改动落点**增量补扫一次（主 agent 自己跑，不必全量重开）——每个改动点问：新措辞与上下文还自洽吗？计数、交叉引用、节号跟着变了吗？补扫发现新问题 → 回 D 表再处置一轮。

## 旧值复扫两轮（强制道）

B6 教训：「逐条处置 ≠ 逐处改透」——逐条改完仍有旧值残留，且 grep 才抓得到。对每条被改的**旧值字符串**全库扫：

1. 第一轮：旧值 `grep -rn` 目标全库（含 steps / SKILL / 相关文档面）——命中即漏改，逐处修。
2. 第二轮：全部旧值零命中复核（订正说明里引用的旧值本身除外）——零命中才准收口。

## 锚点重记

目标已改 → 新 md5 + commit 锚记下（旧锚作废），报告首行以**处置后版本**为准、处置前版本留对照行。
