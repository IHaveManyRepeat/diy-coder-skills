## 1. 类型判定

一个对象是文本，当且仅当：**它的语义是「给人读的字符串」**。按**用途**（不是按内容）命名与归类——源侧口径直译：命名「主标题」而不是「欢迎来到某某」，「表单标签」而不是「邮箱地址」。

**为什么按用途**：文案会改，用途不会。用途稳定的记录在改文案时不需要重新分类。

## 2. 极简草图约定（源笔画推理的唯一存留处）

用户给的是**极简手绘**（几根线代替文字）时：

- **两横线成对 = 一行文字**（一对线 = 一行）；两对相邻 = 两行；以此类推；
- **单横线 = 装饰**（分隔线 / 边框 / 下划线），**不是**文字；
- **例外**：极简缩略图偶尔用单线代替文字——但**默认按「单线 = 装饰」判**，不确定就问一次。

**语义可辨的草图直接读，不用此约定**——图上写着字就读字。**不要拿它反推字号/字重/行高**：那些值取自 `design.yaml.tokens.typography`，不靠线宽猜（这正是源侧 532 行指南被裁的原因）。

## 3. 规格项清单

| # | 项 | 必填 | 取值 / 判据 | 落点 |
| --- | --- | --- | --- | --- |
| 1 | **用途名** | 是 | 主标题 / 副标题 / 区块标题 / 正文 / 说明 / 标签 / 错误信息 / 辅助文本（八选一或组合） | 结构稿的语义元素 + 规格叙述 |
| 2 | **语义层级** | 是 | `h1`（**全页恰好一个**） / `h2`–`h3` / `p` / `span` / `label` | 结构稿元素名——`check` 的 `semantic-html` 判据面 |
| 3 | **字号** | 是 | **必须逐字命中 `tokens.typography.scale`** 的某一项 | 结构稿 `font-size: var(...)` 或白名单值；否则 `audit` 判 `one-off-font-size` |
| 4 | **字族** | 是 | `tokens.typography.family_base` 或 `family_heading`（二选一，不引入第三种） | 结构稿 CSS 变量 |
| 5 | **字重 / 行高 / 字距** | 是 | **写清取值**；不引入 `tokens` 之外的新值（要引入先在 `revisions` 记理由） | 结构稿 CSS |
| 6 | **对齐** | 是 | 左 / 中 / 右 / 两端（一页内同一角色的对齐方式必须一致——跨页一致性判据） | 结构稿 CSS |
| 7 | **文案**（逐语言） | 是 | 图上可读的实际文字**原样取用**（当起始建议）；图上没有就**留空并问一次**，**不编造** | 结构稿文本节点；文案真源是规格 |
| 8 | **字符容量** | 否 | 该位置**最多容纳多少字**（超出会换行/截断/溢出） | 规格叙述 + 结构稿的溢出处理（`text-overflow` / 换行规则） |
| 9 | **行为** | 否 | 会不会变（计数 / 时间 / 用户输入回显）；会的话说明触发源 | `states[].signals` 的对应态 |
| 10 | **分组** | 否 | 是否与其它文本构成一组（如 hero 的主标题 + 副标题 + CTA 文字） | 结构稿的区块归属；**组内用同一套字号档位** |

## 4. 用途 → 字号档位的映射（本件最容易被做错的一条）

源侧的教训是「**角色名 ↔ 字号**必须显式对齐」——否则实现方不知道 `2rem` 属于哪个角色，也不知道标题该配多少行高。diy 侧口径：

1. 先在 `tokens.typography.scale` 里定出**档位**（白名单）；
2. 再给每个**用途**指定它用哪一档（主标题 = 最大档、正文 = 中间档…）；
3. 结构稿里**只能**用第 2 步指定的那一档——「顺手用大一号」会被 `audit` 拦住。

**跨页一致性**（源 `CROSS-PAGE-CONSISTENCY.md:9` 唯一被救的一句）：**看起来相似、扮演同一角色的文字，在所有页面里应给同一套规格**。读完同场景其它页的规格再定本页档位（源 `steps-c:66` `Do NOT draw from memory` 直译）。

## 5. 文案纪律（承母本写作纪律）

- **一条只讲一件事**，不复述上游已写的信息（要引用就引 ID）；
- **不写没有信息量的套话**（「欢迎使用本系统」这类在规格里没有信息量）；
- **面向用户的语言**按 `document_output_language` 写；机器锚点（ID / 枚举 / 文件名 / token 名）逐字保留；
- **错误信息**要写「怎么修」而不是「哪里错了」（源 `experience-example-mobile.md:38-39` 的正例口径：`We couldn't reach the cloud — your work is on this device.`）。

## 6. 状态与示例

文本对象**通常不单独进 `pages[].states[]`**——它随页面的态变化（空态改成什么话、加载中显示什么占位、错误态说什么），因此它的规格按**页态**分述：

| 页态 | 文本对象要写清 |
| --- | --- |
| 悬停 | 会不会变（链接类文字才变） |
| 空态 | **具体的空态文案**（不是「暂无数据」了事） |
| 加载中 | 骨架屏 / 占位文案 / 保持原文字加动效 |
| 错误 | **具体错误文案 + 怎么修** |

```yaml
# design.yaml 该页记录片段
pages:
  - id: P-1
    states:
      - {name: 悬停,  signals: [文字: 下划线出现]}
      - {name: 空态,  signals: [文字: 还没有事项，先加一条]}
      - {name: 加载中, signals: [文字: 正在载入, 形状: 占位条]}
      - {name: 错误,  signals: [文字: 载入失败，检查网络后重试, 图标: 感叹号]}
```

```html
<!-- 语义层级用元素表达，字号/字族走 token 变量 -->
<h1 class="page-title">待办列表</h1>
<p class="page-subtitle">今天要做的三件事</p>
```
