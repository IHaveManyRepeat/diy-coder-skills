## 1. 类型判定

一个对象是文本输入，当且仅当：**用户要在它里面打字**。近亲要分清：

| 近亲 | 与文本输入的区别 | 处置 |
| --- | --- | --- |
| `textarea`（多行） | 允许换行、有字符上限 | 同本清单，另加「行数 / 上限 / 计数显示」三项 |
| 选择器（select / radio / checkbox） | **不是打字**，是从集合里挑 | 不在本清单；按对象类型另记 |
| 只读展示（带框的文字） | 不可编辑 | 按 `heading-text.md` 记（不是输入） |
| 富文本编辑器 | 有格式工具条 | 单列一类；本清单的元素面（label / 错误 / 辅助文本）仍适用 |

## 2. 规格项清单

| # | 项 | 必填 | 取值 / 判据 | 落点 |
| --- | --- | --- | --- | --- |
| 1 | **输入类型** | 是 | 下列六选一（见 §3） | 结构稿 `<input type="…">` |
| 2 | **标签（label）** | 是 | 每个 `document_output_language` 一条；**不准只有占位符没有标签** | 结构稿 `<label for>` 或 `aria-label`——`check` 的 `semantic-html` 判据面 |
| 3 | **占位符（placeholder）** | 否 | 给**示例格式**不给指令（「2026-09-27」好于「请输入日期」） | 结构稿属性 |
| 4 | **辅助文本（helper）** | 否 | 何时显示（常显 / 聚焦时 / 出错前） | 结构稿元素 + 规格叙述 |
| 5 | **尺寸与内边距** | 是 | 走 `tokens.spacing.scale`；触控目标 ≥44×44 | 结构稿 CSS 变量 |
| 6 | **宽度行为** | 是 | 撑满容器 / 固定宽 / 随内容 | 结构稿 CSS |
| 7 | **色**（底 / 字 / 边框 / 占位） | 是 | **只能是 `tokens.color` 里的值** | 结构稿 `var(--color-*)`；裸 hex → `one-off-color` |
| 8 | **状态清单** | 是 | 见 §4 | `pages[].states[]` 的对应态 + 结构稿里看得见 |
| 9 | **校验规则** | 是 | 见 §5（哪条规则、什么时候触发、失败说什么） | 规格叙述 + AC（引 ID 不复述） |
| 10 | **错误文案** | 是 | **逐条规则一条文案**；写「怎么修」不写「哪里错」 | `states[].signals` 的 `错误` 态 + 结构稿 |
| 11 | **交互行为** | 是 | 见 §6 | 结构稿行为注释 |
| 12 | **无障碍** | 是 | `aria-describedby` 关联辅助文本与错误；错误用 `aria-live` 播报 | 结构稿元素属性 |

## 3. 输入类型（六选一）

| 值 | 用途 | 附带判据 |
| --- | --- | --- |
| **text** | 通用单行 | 是否给 `autocomplete`（姓名 / 地址这类能用浏览器自动填的要给） |
| **email** | 邮箱 | 移动键盘类型 + 大小写不敏感 |
| **password** | 口令 | 是否给可见性切换；**自动填充策略要写清** |
| **number / tel** | 数字 / 电话 | 移动键盘类型；`tel` 不做格式强校验 |
| **search** | 搜索 | 清除按钮的行为 |
| **date / time** | 日期 / 时间 | 时区口径；原生控件不可用时的降级 |

## 4. 状态清单（五态，逐态写「看得见的变化」）

| 态 | 必须写清 | 备注 |
| --- | --- | --- |
| **默认** | 底 / 字 / 边框 / 占位符色 | 全走 token |
| **聚焦** | 焦点环（色 + 宽） / 边框变化 | **键盘可达**且有可见焦点环（不能只有鼠标可用） |
| **填充后** | 与默认的差异（是否有「已填」提示） | 无差异就明说无差异 |
| **禁用** | 底 / 字 / 光标 / **为什么禁用** | 「为什么」写进 `states[].signals` 的文字信号 |
| **错误** | 边框色 + **错误文案** + 图标 | **必须至少一条非色彩信号**（图标或文字）——否则 `check` 判 `color-only-signal` |
| **加载中**（若适用） | 是否禁输入 / 是否转圈 | `加载中` 是页面四态之一；输入级加载态写进页态信号 |

## 5. 校验规则（本件最容易漏「什么时候触发」）

每条规则四要素，缺一不可：

| 要素 | 例 |
| --- | --- |
| **判什么** | 邮箱格式 / 必填 / 长度区间 / 与另一字段相等 |
| **何时触发** | 失焦时 / 提交时 / 输入即验（**三选一，写清**） |
| **失败说什么** | 一条具体文案（写「怎么修」） |
| **失败后焦点去哪** | 留在本字段 / 跳到第一个错误字段 |

**默认选择**（源侧经验口径）：**失焦时验格式，提交时验必填**——「输入即验」在打字过程中报错，要显式说明理由才用。

## 6. 交互行为（按五问写全）

1. **聚焦**：光标位置、是否全选、是否唤起键盘类型；
2. **输入**：有无实时反馈（字符计数 / 强度提示 / 自动补全）；
3. **失焦**：是否触发校验（见 §5）；
4. **粘贴 / 自动填充**：是否允许、是否触发同样校验（**要写清**，源侧默认允许）；
5. **提交**：值被送到哪里（引 AC ID），失败时字段回哪个态。

**校验实现面归位**：本技能只写**规格**（规则 + 文案 + 触发时机）；校验的**实现与测试**归 `src` 的实现方与 `diy-test-design` / `diy-e2e-tests`。源 `steps-p/step-07-validation.md`（149 行）的流程**不并入本技能**。

## 7. 示例

```yaml
# design.yaml 该页记录片段（输入对象无独立记录，规格体现在态与信号上）
pages:
  - id: P-1
    states:
      - {name: 悬停,  signals: [边框变深]}
      - {name: 空态,  signals: [文字: 还没有事项，先加一条]}
      - {name: 加载中, signals: [图标: 转圈, 输入禁用]}
      - {name: 错误,  signals: [文字: 邮箱格式不对，检查有没有 @, 图标: 感叹号]}
```

```html
<label for="email">邮箱</label>
<input id="email" name="email" type="email" autocomplete="email"
       aria-describedby="email-help email-error" />
<p id="email-help">用来接收通知，不会公开</p>
<p id="email-error" aria-live="polite">邮箱格式不对，检查有没有 @</p>
```
