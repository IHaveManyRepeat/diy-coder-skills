**用途**：`[P] Specify` 第 3 步与 `[M]` 活动逐对象定类型时，按本清单**逐项写规格**——本件回答「一个按钮有哪些项要说清」，不回答「怎么跟用户一问一答」（问答流程在 `steps/p-specify.md`，裸路径按本技能安装目录解析）。

## 1. 类型判定

一个对象是按钮，当且仅当：**它有「按下 → 发生一件事」的语义**（提交 / 保存 / 继续 / 取消 / 删除 / 跳转）。只有样式像按钮但语义是链接的（导航为主），按 `link.md` 记——**语义定类型，样式不定类型**。

## 2. 规格项清单

逐项写。**落点列**给出该项在 diy 产物里的位置（写不进去的项说明它不该写）。

| # | 项 | 必填 | 取值 / 判据 | 落点 |
| --- | --- | --- | --- | --- |
| 1 | **类型（语义层级）** | 是 | 下列六选一（见 §3） | `states[].signals` 的文字信号 + 结构稿的语义元素（`<button type>` / `<a role="button">`） |
| 2 | **文案**（每个 `document_output_language` 一条） | 是 | 动词开头，一条只讲一件事；不编造翻译 | 结构稿文本节点；多语言项目逐语言确认 |
| 3 | **图标** | 否 | 有无 / 位置（前 / 后 / 仅图标） / 图标名 | 结构稿的 `<svg>` 或图标组件引用；**仅图标时文案项转为 `aria-label`**（无障碍必需） |
| 4 | **尺寸与内边距** | 是 | 只能取 `tokens.spacing.scale` 的值；零间距也要写明 | 结构稿的 CSS（`var(--space-*)`） |
| 5 | **圆角与描边** | 是 | 值须与项目既有页一致（跨页一致性） | 结构稿的 CSS；**若引入新值**先在 `revisions` 记理由 |
| 6 | **色**（默认 / 悬停 / 激活 / 禁用 各自的底与字） | 是 | **只能是 `tokens.color` 里的值**（`bg` / `surface` / `text` / `accent` / `accent_text`） | 结构稿的 `var(--color-*)`；不准出现裸 hex（`audit` 会判 `one-off-color`） |
| 7 | **状态清单** | 是 | 见 §4（默认 / 悬停 / 激活 / 禁用 / 加载中） | `pages[].states[]` 的对应态 + 结构稿里看得见的四种表现 |
| 8 | **点击后的完整流程** | 是 | 见 §5 的七问 | 结构稿的行为注释 + `stories.yaml` 的 AC（**引用 ID，不复述**） |
| 9 | **可点击的前置条件** | 否 | 表单校验 / 必填项 / 需登录 / 其它前置 | `states[]` 的 `错误` / `禁用` 态信号 + AC |
| 10 | **无障碍** | 是 | 见 §6 | 结构稿（`aria-label` / 焦点可见 / 触控目标 ≥44×44） |

**归属提醒**：若这个按钮**第二次出现**（同样的态、同样的行为），它就是一个真模式——**报给 `diy-wds-system`**（`components[]` 的「二次使用才提取」阈值），本技能**不自行铸组件**。

## 3. 类型（语义层级，六选一）

| 值 | 用途 | 判据 |
| --- | --- | --- |
| **Primary 主行动** | 这一页最该被点的那个 | 一屏**至多一个**；与 `direction` 的强调色规则一致 |
| **Secondary 次行动** | 替代路径（取消 / 返回） | 与主行动**同屏可见**，但视觉权重更低 |
| **Tertiary / 文字按钮** | 低优先（跳过 / 了解更多） | 无底无框，只有文字 |
| **Destructive 破坏性** | 删除 / 移除 / 不可逆 | 必须与主行动**分开**，且点击后要有二次确认（把确认写进交互流程第 3 步） |
| **Icon 图标按钮** | 只有图标 | **`aria-label` 必填**（没有它，屏幕阅读器读不出来） |
| **Link 按钮** | 样式是按钮、语义是导航 | 按 `link.md` 记（`target` / 新标签页 / `rel`） |

## 4. 状态清单（五态，逐态写「看得见的变化」）

| 态 | 必须写清 | diy 落点 |
| --- | --- | --- |
| **默认** | 底 / 字 / 边框（全走 token） | `pages[].states[].signals` 的常态表现 |
| **悬停** | 底 / 字 / 边框 / 附加变化（阴影、位移） | **必须有一条非色彩信号**：颜色不能单独承载语义（`check` 的 `color-only-signal` 判据） |
| **激活 / 按下** | 底 / 字 / 视觉反馈（缩放、阴影移除） | 同上 |
| **禁用** | 底 / 字 / 光标 / **为什么禁用** | 「为什么禁用」写进 `states[].signals` 的文字信号 |
| **加载中**（若适用） | 是否转圈 / 加载文案（逐语言） / 是否禁掉其它交互 | `加载中` 是四态之一，**不许省**；不适用也要给**最小真实信号**并注明 |

**四态是下限**：异步密集的页面可追加 `离线` / `权限拒绝` / `冷启动` 等状态（`validate` 是子集判定，追加即合法），追加项同样要 ≥1 条非色彩信号。

## 5. 交互与行为（点击后，按七问写全）

1. 用户点了什么；
2. 按钮自己变成什么态（`加载中`？`禁用`？）；
3. 系统做了什么（校验 / 请求 / 本地状态变更）——**指向 AC 的 ID，不复述 AC 的句子**；
4. 成功之后发生什么（去哪 / 页面变成什么）；
5. 失败之后发生什么（错误文案长什么样、按钮回哪个态）；
6. 用户**看到**什么（可见的反馈，不是内部日志）；
7. 要不要导航（要的话写目标页 ID：主线 `P-n` / WDS 线 `SC-<nn>.P<n>`）。

**缺一不可**：第 5 问（失败路径）在源侧范例里是「在表单上方显示错误」这类**具体到可见行为**的描述——写「处理错误」等于没写。

## 6. 无障碍与校验（可机械核对的部分）

| 项 | 判据 |
| --- | --- |
| 触控目标 | ≥ 44×44（源 `INLINE-TESTING-GUIDE` 的可测项口径） |
| 焦点可见 | 键盘可达且有可见焦点环（对比度按 3:1 起） |
| 名称 | 纯图标按钮有 `aria-label`；有文字时用文字 |
| 对比度 | 底/字配对走 `check` 的 `contrast` 判据（≥4.5:1），**配对集合以引擎回执 `checked.contrast_pairs` 为准，不自拟子集** |
| 表单前置 | 校验失败时的错误文案与错误态信号一一对应（不能只有红框没有字） |

## 7. 示例（改写后）

```yaml
# design.yaml 该页记录片段（按钮在这个体系里没有独立记录，规格体现在态与信号上）
pages:
  - id: P-1
    states:
      - {name: 悬停,  signals: [底色加深, 图标微移]}
      - {name: 空态,  signals: [文字: 还没有事项，先加一条]}
      - {name: 加载中, signals: [图标: 转圈, 文字: 正在保存…, 其余交互禁用]}
      - {name: 错误,  signals: [文字: 保存失败，请重试, 图标: 感叹号]}
```

结构稿片段（**token 变量、四态可见、语义元素正确**）：

```html
<button type="submit" class="btn-primary">
  <span class="btn-label">保存</span>
</button>
<!-- 悬停/激活/禁用靠 CSS 的 :hover / :active / [disabled]；加载中把 label 换成「正在保存…」并 disabled -->
```
