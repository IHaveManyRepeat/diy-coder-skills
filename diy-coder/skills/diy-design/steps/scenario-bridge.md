# Step — 场景桥（主线上行：功能清单 → 场景/页面树）

Progress: `[1 读功能清单] → [2 生成场景/页面树] → [3 用户确认（硬门）] → [4 落 pages[] 骨架] → 收尾路由`

**Read (input):** `{output_dir}/prd.yaml` 的 `features[]`（`FG-*`）与其 `requirements[]`（`FR-*` / `F-*`，逐条 `statement`）；`{output_dir}/architecture.yaml` 的 `stack[]`（框架取值，见规则 6，可选）；既有 `{output_dir}/design.yaml`（续跑时）；用户在本文件各步的回答。
**Write (output):** `{output_dir}/design.yaml` 的 `pages[]` **骨架**（`id` / `name` / `route` / 空 `states[]`）与 `project` 块；给用户的页面树呈批。

你是**设计总监**。这一段是**主线上行**：`prd.yaml` 里只有功能清单，没有页面——「桥」要从功能清单长出场景/页面树，**请用户确认后**才进逐页规格。

〔**源侧对照**〕源 wds-4 的页面树来自 `steps-s/step-05..15`（7 步场景定义 + 8 步页面定义，共 1,997 行）。diy 主线**不搬那套对话**：页面树的**唯一取数源是 `prd.yaml` 的功能清单**（母本检测面已锁在 FR），源侧那 15 步由下方 4 步 + `steps/c-discuss.md` 承接。

## 第 1 步 —— 读功能清单

逐条读 `features[].requirements[]`，只取**前端面** FR（`design.py detect` 已判过 `has_frontend: true`，此处不重跑启发式）。每条 FR 抽三样：**用户要达成什么**（目的）、**在哪个入口触达**（入口）、**达成后去哪**（出口）。

**本段纪律**：**不许凭印象补页**——每个待确认的页都要指出它承接的 FR ID；找不到 FR 的想法当场记进 `open_questions`（`status: 待办`），不写进 `pages[]`。

## 第 2 步 —— 生成场景/页面树（复杂度启发式）

把 FR 聚类成**场景**（一条场景 = 一串有先后关系的页），再按下面的**复杂度启发式**判「该拆页还是一页装下」。判据取自源侧 `data/object-types/COMPLEXITY-ROUTER.md:30-37` 的复杂度指标（该文件其余部分按裁定 4 裁撤，仅此判据保留）：

| 信号 | 判为 | 处置 |
| --- | --- | --- |
| 单态、无交互、无数据依赖、无业务规则 | **简单** | 并入所在页的一个区块，不单独开页 |
| **3+ 状态**（空/加载/进行/完成/错误） | **复杂** | 单独开页或独立区块，`states[]` 逐态写 |
| **时变**（倒计时、实时更新） | 复杂 | 同上，且必须给非色彩信号 |
| **多步交互**（预订 → 开始 → 完成） | 复杂 | **一步一页**（阳光路径），页号连续 |
| **业务规则**（校验、权限、阻断） | 复杂 | 独立页或独立态，规则一句话写进 `states[].signals` |
| **数据同步**（改动影响其它视图） | 复杂 | 独立页，并在 `states[]` 的 `错误` 态写清不同步的表现 |
| **状态机**（有定义的迁移路径） | 复杂 | 逐迁移路径一页，`pages[].status` 承接迁移 |

**判据互斥声明**：本表的**组件级**版本（「一个对象该不该拆成组件」）归 **`diy-wds-system`** 的 `data/complexity-router.md`——本技能**只持有页面树这一侧的判据，不复述组件侧那份**（单一源，避免两技能各持一份）。

**产出物形态**：一张页面树呈出（每页一行：编号 / 页名 / 入口 / 出口 / 承接的 FR ID），**不落独立 md**（单一源 = `design.yaml.pages[]`）。

## 第 3 步 —— 用户确认（硬门）

**结构先行通则**（全技能统一）：**先出结构、经用户确认，再进详细规格**。本步是该通则在本入口的具体化：

- 呈出页面树 + 每页承接的 FR ID + 你对「为什么这样拆」的一行理由；
- **没拿到明确点头不许进 `[P]` 写规格**——用户改结构就改页面树再重呈；
- 用户说「这页不要」→ 该页在落盘时**不写进 `pages[]`**（而不是写一条再删）；若已写过则走 `design.py transition --to 已移除 --reason <文案>`（`已移除` 是终态之一，留痕不删记录）。

## 第 4 步 —— 落 `pages[]` 骨架

用户点头后写盘。形状（**只写骨架，`states[]` 留到 `[P]`**）：

```yaml
project: {name: <prd.yaml 的 project.name>, status: 草稿, created: <今天>, updated: <今天>}
pages:
  - id: P-1            # 主线页 ID 域 `P-n`：顺序铸号、不重编不复用；WDS 线另用 SC-<nn>.P<n>
    name: <页名>
    route: <路由>
    # status 骨架期不写——缺省即 `未开始`；首次推进经 design.py transition 落键
    states: []         # 第 [P] 活动补齐（四态不许省）
    prototype: prototypes/P-1.html
revisions: []
```

**铸号纪律**：`P-n` 按顺序递增；删页**不复用**它的号，也不重排其余页（`P-1` / `P-3` 并存是合法的，`P-2 → P-1` 的重编是**禁止**的）。

**落盘后的自检**：`design.py validate --design "{output_dir}/design.yaml"` 此时**必然 FAIL**（`states[]` 空）——这是预期，**不是**跳过四态的出口；把回执原样呈给用户，说明下一步就是逐页补四态。

**检查点**：① 生成 → ② 落盘 `pages[]` 骨架 → ③ 分隔 → ④ 呈出页面树与回执 → ⑤ 给下一步选项 → ⑥ 等响应。

**收尾与路由**：页面树已定，读 `./c-discuss.md` 逐页做创意对话（或用户点名直接走 `./p-specify.md` / `./prototype-loop.md`）。

本文件到此结束，不再回头。
