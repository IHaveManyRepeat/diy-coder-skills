# Step — [C] 创意对话（Discuss）

Progress: `[1 载上下文] → [2 摆场景] → [3 D1 主行动] → [4 D2 能否砍掉] → [5 自然讨论与摘要] → [6 收尾路由]`

**Read (input):** `{output_dir}/design.yaml` 的 `pages[]`（目标页记录与已定页面树）；`{output_dir}/prd.yaml` 的该页承接 FR（主线）或 `{output_dir}/wds-scenarios.yaml` 的该页记录 `SC-<nn>.P<n>`（WDS 线）；**同场景其它已设计页的记录**（找既有模式——源侧明令 `Do NOT draw from memory`）；用户在本文件各步的回答。
**Write (output):** 该页的讨论结论（`name` / `route` / `states[]` 的雏形 / 新增页或删页的判定）；`revisions` 追加（有用户改动时）；`design_status`：WDS 线的讨论定稿写 `discussed`、**整条场景废弃写 `removed`**（场景级键，值域见主文件规则 1）。

你是**设计总监**。这一段是**每页两问**：先把这一页摆到台面上，再问「它最该干什么」「它能不能不存在」。**只问、不代答**——你带设计判断，用户带产品知识。

〔**源侧直译**〕源 wds-4 `steps-c/step-01-exploration.md`（332 行 / 内部 9 段）。diy 侧裁掉的是**平台耦合**（Excalidraw + VS Code 扩展 + 人工导出 PNG 的审批闸，源 `:146-174`）与**设计日志散 md**（源 `:256-293`）；判据与两问一字不动。

## 第 1 步 —— 载上下文

读该页记录 + 它承接的 FR / 页面记录 + **同场景其它已设计页**（主线 = `design.yaml` 里同批 `pages[]`；WDS 线 = `wds-scenarios.yaml` 同 `SC-<nn>` 下的兄弟页）。抽出：既有导航模式、既有共享组件（`diy-wds-system` 的 `components[]`，只读）、既有布局约定。

**本段纪律**：**不许凭记忆画**——「这个项目通常怎么做」一律以**读到的记录**为准（源 `steps-c:66` `Do NOT draw from memory`，直译）。

## 第 2 步 —— 摆场景

用一段话把这一页摆出来：用户是谁（引 `wds-scenarios.yaml` 的 `trigger_map_context.target_group` 或 `prd.yaml` 的 `users[]`）、他从哪来（`entry_context`）、他要达成什么（`purpose`）。**先摆再问**——不问空问题。

## 第 3 步 —— D1：用户在此页最该做什么

一问一答。**不许给多选题式的诱导**；把问题原样问出来，等回答。回答落成该页的**主行动**记录（一句话，写进 `name` 的注释或 `direction` 的对应禁令行——它决定后面所有取舍）。

## 第 4 步 —— D2：这页能不能砍掉 / 简化

第二问。三种结论：

| 结论 | 处置 |
| --- | --- |
| **能砍** | 改场景/页面树：该页**不写进 `pages[]`**；若已写过 → `design.py transition --design "{output_dir}/design.yaml" --page <id> --to 已移除 --reason "<为什么砍>"`（`--reason` 必填）；随后检查有没有兄弟页承接它的出口 |
| **能并** | 合并进相邻页的一个区块；同样按「已移除」处置被并页并说明去向（写进 `--reason`） |
| **不能砍** | 进第 5 步（这一页的讨论到此结束，不再追问） |

**阶段限定**：上表是**设计期**的页级废弃（写权归本技能）；**实现期**确认废弃（页已进 `结构稿中` 之后）归 `diy-dev` 的 WDS 模式——同一条边两阶段显式分工，非写权漂移。
**场景级废弃**：若用户废弃的是**整条 `SC-<nn>`**（不是单页）→ 把该场景的 `scenarios[].design_status` 推到 `removed`（场景级键，**只写这一个键**；页级 `pages[]` 的处置按上表逐页走）。

〔**源侧缺陷修复**〕源侧此处分三步走「改场景大纲 → 删页面文件夹 → 追加 `removed` 状态」（`steps-c:104-109`）——diy 侧**没有页面文件夹**（单一源 = `design.yaml`），故压成**一条 `transition` 命令 + 页面树修订**。源侧 `removed` 值不再直译（裁定 5 已把全链 10 个状态承载位收敛为 5 值：`未开始 / 结构稿中 / 待验收 / 已批准 / 已移除`）。

## 第 5 步 —— 自然讨论与摘要

讨论点什么由用户带：这一页的语气、必须出现的内容、绝不要出现的东西。每轮讨论**收一条一句的结论**（源 `:194-254` 的「两问过渡」四副本压成此处一处）：

1. 本页要不要继续？（`[C] Continue` / 用户打住）
2. 继续的话：进 `[P]` 写规格、还是先出结构稿（`[W]` / `./prototype-loop.md`）？

**摘要**（呈出，不落独立 md）：页名 / 主行动 / 承接 FR 或 `SC-<nn>.P<n>` / 讨论里定下的 2–3 条硬约束。

〔**裁撤登记**〕源侧「可视化三选一」菜单（线框 / 自供草图 / 直接写规格，源 `:139-174`）在 diy 侧**不收编为菜单**：结构稿恒为 `prototypes/<页 id>.html`（`[W]` 活动），用户自供的草图走 `[K]`（`./k-sketch.md`），「直接写规格」走 `[P]`——三条路都在，只是不再由一段菜单驱动。源侧 Excalidraw 线框与「人工导出 = 审批门」**裁**（X6）：diy 的审批门是 `pages[].status` 转 `待验收` / `已批准`（经 `transition`），**两个写者都在下游**——`待验收` 归 `diy-dev` 的 WDS 模式（实现 + 自验后才写）、`已批准` 是**用户批准**（人裁，不代批）；本活动不写这两个值。

## 第 6 步 —— 收尾路由

落盘 → 检查点（① 生成 ② 落盘 ③ 分隔 ④ 呈出摘要 ⑤ 给选项 ⑥ 等响应）→ 按用户选择读 `./p-specify.md` 或 `./prototype-loop.md`。

WDS 线附带：该 `SC-<nn>` 的**全部页**讨论定稿后，把 `scenarios[].design_status` 推到 `discussed`（**从当前值推进即可**，不假定 `not-started`；**只写这一个键**，其余字段只读；该键是场景级，页级进度写 `pages[].status`）。

本文件到此结束，不再回头。
