# Step 3 — 客户痛点与未满足需求（market 维度）

Progress: `Scope → 02 Behavior → [03 Pain Points] → 04 Decisions → 05 Competitive → Synthesis`

**Read (input):** `{output_dir}/research.yaml` 里本记录；第 2 步的 findings。
**Write (output):** 痛点 findings 写进该记录；本步播报。

## 关注面

- 客户面临的难题与挫败
- 未满足的需求与未解决的问题
- 采用或使用上的障碍
- 服务与支持的痛点
- 客户满意度缺口

## 检索（并行跑）

- `"{topic} customer pain points challenges"`
- `"{topic} customer frustrations"`
- `"{topic} unmet customer needs"`
- `"{topic} customer barriers to adoption"`

## 要写的 findings

每个 `area` 一条 `findings[]` 条目，随该次检索落地即写：

| `area` | 该断言说什么 |
| --- | --- |
| `challenges-frustrations` | 主要挫败点、使用障碍、发生频率 |
| `unmet-needs` | 关键未满足需求、解决方案缺口、市场缺口 |
| `adoption-barriers` | 价格、技术、信任、便利性障碍 |
| `service-support` | 客服问题、支持缺口、响应时长 |
| `satisfaction-gaps` | 期望 / 质量 / 价值感知 / 信任缺口 |
| `emotional-impact` | 挫败严重度、忠诚与流失风险、口碑影响 |
| `prioritization` | 高 / 中 / 低优先级、机会映射 |

## 方法

- 必须联网检索——满意度调查、评价、投诉数据、支持论坛。
- 每条 `critical claim` 两个独立来源；冲突来源两边都摆。
- 每条 finding 的 `confidence`：`高` / `中` / `低`，理由要在断言里看得见。
- 优先级判断必须以证据为据（有记录的缺口），不能只凭直觉。
