# 描述优化闭环

当用户要的不只是「量一下触发」，而是「把描述改好」时，按本闭环走。核心风险是**自欺**：用同一批问句又改又验，改到能过为止——那条描述只学会了这批问句。分层切分与测试集盲化就是防这个。

## 一、造近邻问句（约 20 条）

一半**该触发**、一半**不该触发**，且两半共享关键词——**关键信号就在近邻里**：只测「明显该触发」和「明显无关」的问句，任何描述都能过。

- 该触发：真实用户会怎么开口（口语、错别字、半句上下文、只给目标不给方法），而不是把技能描述抄一遍。
- 不该触发：共享同一批关键词、但意图落在**别的技能或纯聊天**上的问句（这正是描述过宽劫持会话的地方）。

## 二、分层切分（60/40）并**全程固定**

按「该触发 / 不该触发」两层各按比例切出训练集与测试集，**切分一次定死、全程不重洗**。之后所有轮次都用同一套切分——重洗一次，前面比出来的分数就全作废。

## 三、每问句多跑几次

触发是概率事件：一条问句只跑一次就是掷硬币。用 `--runs N`（≥3）得到触发率，对阈值判 pass（阈值缺省 `0.5`）。

## 四、只把**训练集**的失败交给改进者

**测试集标签与分数全程保密**——改进者永远看不到测试集的正确标签与得分。只看训练集失败，才能保证最后那次「测试集也认可」是泛化，不是背题。

## 五、回喂已试与失败原因

把**已经试过的描述**连同它们的失败原因一并交给改进者。不回喂的话，下一轮很可能改回上一轮的措辞，在两个版本之间来回振荡、轮数耗尽。

## 六、≤5 轮 + 早停

上限 5 轮。训练集上干净分离、且测试集认同 → 提前停。

## 七、按**测试集**分数择优

最终选用的描述按测试集分数定，不是按训练集、也不是按最后一轮。并列时先看训练集；再并列取更短、更利落的那条。

## 八、全程留痕

每一轮试了什么描述、训练集/测试集分数、为什么改，都追加进 run 的 `.memlog.md`（`mlog --dir <run 目录> append --file .memlog.md --type direction --text "<一句话>" --project-root "{project-root}" --output-dir "{output_dir}"`）。下一次谁来接手，读这一条就知道已经走过哪些坑。

## 反模式

- 把测试集当训练集用（或「就这一次」看一眼正确标签）——那一轮之后所有分数都不可信。
- 改到测试集只差一条就盯住那一条改——过拟合单条问句，描述会变脆。
- 描述里堆 `ALL-CAPS MUST`、把所有关键词塞一遍——近期句会全触发，近邻负例全误触发。这是黄旗，不是解法。
