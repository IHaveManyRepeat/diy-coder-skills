# Step 4 — 收敛组织与行动计划（Organize）

Progress: `会话设置与续接 → 技术选取 → 教练执行 → [组织] → 收尾`

**Read (input):** 本记录的 `topic` / `goals` / `techniques` / `ideas`（组织对象）。
**Write (output):** 记录的 `themes` / `priorities` / `actions`；`current_step: 5`（选 `[C]` 时）；给用户的组织结果。

## 开场：先回顾

一句话给出会话成绩单：想法总数（`ideas` 条数）、用过的技术（`techniques`）、议题与目标。然后明说「接下来把这些想法收敛成主题、优先级与行动计划」。

## 一、主题聚类 → `themes[]`

- 把想法归成 **3 个左右的主题**，每个主题写 `name`（主题名）+ `focus`（这个主题在解决什么）+ `ideas`（本主题的 `no` 列表）。
- 另给三个**横切视角**（别强行塞进主题）：
  - **交叉想法**：横跨多个主题的；
  - **突破概念**：最新颖、最意外的；
  - **可落地想法**：看起来立刻能动的。
- 这三类不是新字段——用 `themes` 的一条收（name 写「横切 / 突破 / 可落地」），或在对话里呈现后只把用户认可的写进 `themes`。
- 呈现给用户：「哪个主题或哪条想法对你最重要？」

## 二、优先级 → `priorities`

按四维引导用户自己排序（四维名的语义逐条保留）：

| 维度 | 判据 |
| --- | --- |
| Impact | 对 `<议题>` 成败的潜在影响 |
| Feasibility | 落地难度与资源要求 |
| Innovation | 原创性与差异化优势 |
| Alignment | 与既定目标 / 约束的贴合度 |

产出三组 `no`（可重复、可空，但 `top` 必须非空——收尾态要求）：

- `top`：**高影响 Top 3**（最高结果潜力）
- `quick_wins`：**最快见效**（先做哪个最容易成）
- `breakthroughs`：**真正的突破**（可能慢，但改变游戏规则）

**排序由用户拍板**——你给判据与自己的看法，禁替他决定。

## 三、行动计划 → `actions[]`

对每条入选想法（至少 top 的那几条）写一条行动计划：

- `idea`：引用的 `no`（必须在 `ideas[].no` 内）
- `why`：为什么这条值得先动（接回 `goals` 的措辞）
- `steps`：**下一步具体动作**（可执行到"这周能开始"，2-5 条）
- `resources`：需要什么（人 / 信息 / 工具）
- `timeline`：一个时间估计
- `success`：怎么算成了（成功指标）

问用户「要不要给其它高优先级想法也配一条」——**没有行动计划的收尾会被终门拒绝**（`themes` / `actions` / `priorities.top` 三者非空是 `current_step: 5` 的硬要求）。

## 四、收束

- 呈现总览：N 条想法 / M 个主题 / K 条行动计划；谁负责、从哪开始。
- 菜单：`[C] 完成本次会话` / 其它（想再发散 → 回 `./03-facilitate.md`；想调主题/优先级 → 留在本步就地改）。
- 选 `[C]` → 记录 `current_step: 5`，然后

读全并照做 `./05-finish.md`。
