**本段纪律**：① **不跳读**：本步只读它点名的那一份产物，绝不批量预载 `steps/`；前一步的产物没落盘，本步不许开工。② **不编造**：读不出来的值留空并记 gap；绝不用印象补。③ **不代决**：检查点呈出后 HALT 等响应，绝不替用户拍板。④ **不问出已知**：问题与范围从用户口述与上游材料里**读出来**，不拿一张空白问卷从零问起。

## 第 1 步 —— 成文问题与定范围（源 step-01 第 1–2 指令）

**先说清为什么**：讲清「为什么先有一句话的问题，才准翻开第一个文件」——源侧把这一步的失败模式点得很直白：没有问题时探索是**漫无目的**的，读得越多越糊涂。用你自己的话讲。

**成文问题**（源 step-01 第 1 指令，七类问题分类表**全保**）：

| 类别 | 例 |
| --- | --- |
| **架构** | 这个应用是怎么组织的？用了哪些模式？ |
| **依赖** | 这个模块依赖什么？改它会连带坏掉什么？ |
| **模式** | 团队遵循哪些约定？哪里不一致？ |
| **性能** | 瓶颈在哪？哪些查询最贵？ |
| **数据流** | 数据从用户输入到落库再回来，走哪条路？ |
| **集成** | 它连了哪些外部服务？怎么连的？ |
| **安全** | 认证在哪处理？有没有裸奔的端点？ |

用**大白话**写进 `question.text`；有多个问题就先排序，**一次只做一个**（其余记 `revisions` 当下一轮的输入）。

**定范围**（源 step-01 第 2 指令，四档**全保**）：`scope` 取——**整个代码库**（入职 / 补文档用）/ **单个模块**（一个功能区、一个服务、一个包）/ **跨切面关注点**（认证、错误处理、日志）/ **集成边界**（两个系统怎么说话）。**明确写出什么不在范围内**——无界范围必然导致分析瘫痪。

**落盘**：本步结论先记在会话里；写盘统一在第 2 步的 `init` 一次完成。

**检查点（六拍）**：① 生成 → ② 落盘 → ③ 分隔 → ④ 呈出 → ⑤ 出四选项 → ⑥ 等响应。本步：② 落盘（本步无写盘，仅记本步结论）；④ 呈出问题与范围。

## 第 2 步 —— 产出形制、时间盒与铸骨架（用户关卡 + 门禁）

**先说清为什么**：讲清「为什么要先说清交什么、花多久」——产出形制决定你扫的时候盯什么，时间盒是**防分析瘫痪**的唯一闸门（源侧把它列为 Critical Rule）。用你自己的话讲。

### 2.1 产出形制（源 step-01 第 3 指令）

`question.output_format` 六选一或组合：**架构图** / **依赖图** / **模式目录** / **API 地图** / **数据模型** / **风险评估**。

### 2.2 时间盒（源 step-01 第 4 指令）

`question.time_box` 按范围档取值：单模块 15–30 分钟 / 功能区 30–60 分钟 / 全代码库 1–2 小时。**时间盒到期就停手**：把已找到的与还没看的都写下来（源 `If the time box expires, document what you found and what remains unexplored`）。

### 2.3 门禁与铸骨架（`init`，用户关卡之后才铸）

**门禁 = 代码库可读**（本技能无上游 diy 产物）：

- `--codebase` 缺席 → 默认 `{project-root}`；路径不存在 / 不是目录 / 不可读 → `init` 判 `MISSING_FILE`、**零产出**，你一行说明后停手（若用户的真实目标是「体检任意项目的架构」，见 SKILL.md 激活段第 3 步的边界句，路由 `arch-analyze`）。
- 上游产物：**无**——`diy-analyze` 是入口技能，不读任何 diy 产物，也不被任何门禁引用。

**用户关卡**：把问题 / 范围 / 形制 / 时间盒四项摆成一块呈批（形如「本题：……；范围：……（不含：……）；交什么：……；时间盒：……。看着对吗？」），**没拿到明确点头就不许往下走**；点头后调引擎：

```
python "{project-root}/.claude/skills/diy-analyze/scripts/analyze.py" init --question "<问题>" [--scope "<范围>"] [--output-format "<形制>"] [--time-box "<时间盒>"] [--codebase "<路径>"] --project-root "{project-root}" --output-dir "{output_dir}" --json
```

- `--question` 空 / 全空白 → `EMPTY_FIELD`（零产出）；门禁不过 → `MISSING_FILE`（零产出）。
- 已有 `analysis.yaml` → **不覆盖**：只刷 `project.updated` 并回 warning `ALREADY_EXISTS`（要改内容就地编辑，改既有条目往 `revisions` 追加）。
- 产物损坏 → `UNPARSABLE_YAML` 拒绝，零写入。
- `project.name` / `created` / `question` 五项由 `init` 一次铸成；**`project.name` 与 `created` 此后不再由你改**。

**检查点（六拍）**：① 生成 → ② 落盘 → ③ 分隔 → ④ 呈出 → ⑤ 出四选项 → ⑥ 等响应。本步：② 落盘（`init` 铸骨架 + `question` 五项）；④ 呈出回执与骨架摘要。 四选项同第 1 步。

**收尾与路由**：问题与门禁都过了，读 `./02-scan.md` 起广度侦察。
