# 代码质量理念

> v4·精简插队批立（2026-10-15）。全库 scripts 面施工与评审的共同准则；与旧习惯冲突时以本文件为准。

1. **查后再写**：写新工具函数前先查 `diy-tools/scripts/diyc_lib.py`——有则 import 使用；确无合适的，新通用函数提炼回 diyc_lib。
2. **DRY 单源**：同一逻辑全库只留一份；发现重复先收敛再动手，不做复制式修改。
3. **KISS/YAGNI**：只实现当前明确所需的功能；拒绝投机性抽象与「未来可能用到」的预留。
4. **单脚本单职责，单文件 ≤400 行**（典型 200-300）；超线即拆，命名＝`{skill}_lib.py`（工具面）／`{skill}_checks.py`（校验面）；技能内多脚本＝常态（先例：diy-tools 6 件、test-gate 3 件）。
5. **底座唯一**：全量安装前提下，公共函数唯一去处＝`diy-tools/scripts/diyc_lib.py`；**技能间不互相 import 对方脚本**。
6. **名实一致**：名字说什么，代码就得做什么；职责变了名字跟着变。
7. **死代码零容忍**：零消费即删，不留「以防万一」。
8. **测试即门**：全量测试零红＋sync 源装 md5 全同，才算完工。
